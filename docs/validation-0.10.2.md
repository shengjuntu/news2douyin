## 查询与队列

- 过滤和分页前计算全局排队序号；只查看每日脚本或视频时仍显示其在整个队列中的位置。
- 同时入队时按任务编号稳定排序，与执行器认领规则一致；取消、重试、认领后序号按真实记录变化。
- 全局统计与筛选数量分别返回；区分排队、执行、正在取消、失败、完成和已取消。
- 验证 125 条记录的后续分页；字面 `%`、`_`、反斜线不会被当成搜索通配符。
- 日期筛选在计数与分页前执行，覆盖 Asia/Shanghai 与 UTC 的跨日边界及带偏移的旧时间戳。
- 耗时区分本轮排队、当前执行与首次提交到结束。缺失日期显示未知，未来时钟差不显示负数；不会把重试前的执行时间误算成本次执行。
- 执行状态过期可以被识别，但只读查询不会修改状态、续期、恢复、重试或新增任务事件。
- 查询不暴露固定配置、模拟密钥、请求指纹或租约令牌；结果链接按任务类型生成，不读取媒体文件或解析完整生成输入。

## 浏览器

`tools/smoke_task_monitor.py` 提供包含 117 条记录的临时测试服务，明确控制执行器启停和采集响应。浏览器通过 `tools/smoke_task_monitor_browser.cjs` 验证：

- 本地执行器停止提示、启动后的当前执行与等待队列。
- 过滤保留全局排队序号，筛选 URL 刷新可恢复；历史记录超过 100 条时可分页与浏览器返回。
- 单任务取消后显示结束，重试后重新显示位置；前面的任务被认领后位置自动前移。
- 暂停/恢复自动刷新，完成后概览和详情更新；请求 503 时保留旧数据并说明状态可能已过时。
- 失败入口能进入既有处理页，完成的每日任务能直接打开原稿。
- 桌面与 390px 手机宽度没有横向溢出，无 JavaScript 异常。

## 安装与旧版继续执行

升级夹具由已安装的 **0.10.1 wheel** 创建：包含已完成的每日稿、一项保存中断但已有生成稿检查点的任务，以及一项排队采集任务。安装 **0.10.2 wheel** 后：

1. 打开原数据库与运行目录。所有原任务行、任务事件、每日生成输入/结果关联和已完成稿完整快照逐项相同。
2. 读取新监控接口后原数据仍保持相同，旧队列位置正确。
3. 重试旧失败任务后，它排到原采集任务之后。原采集成功执行，失败的每日任务复用保存的生成稿完成，没有再次调用生成函数。
4. 原有稿件不变，监控页给出新完成稿的正确链接。

全部安装检查使用 `python -I`，确保代码与模板来自发行 wheel。报告为 `validation-0.10.2/wheel-*.json`。复现使用 `seed_upgrade_0_10_1.py` 与 `smoke_task_monitor_installed.py --upgrade-fixture`，见 `tools/README.md`。
