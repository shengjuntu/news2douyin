# 自然语言专题与持续跟踪

## 建立专题

在“我的专题”填写一段描述，说明关注对象、关心的变化以及希望弄清的问题。例如：

> 持续跟踪特朗普政府对俄乌战争的政策变化，重点关注对乌军援、对俄制裁、停火谈判及美欧协调。少看私人生活，希望了解政策变化的历史背景和实际影响。

生成后检查专题名称、关注范围和初始问题，再开始跟踪。实体和关系图、手动范围等细节可以按需展开，不要求用户编辑图数据库查询或JSON。

一段描述可以涵盖多个关注分支，不要求一条新闻同时包含所有实体。人物、组织、地区、行动及别名用于帮助找到候选，新人物也可能通过行动或议题进入候选。

## 关注图和材料图

关注图描述用户希望寻找的关系。例如“关注是否暂停军援”是一条关注模式，并不证明军援已经暂停。相关报道和正文抽取的动作陈述有各自的来源与版本。

AGKG继续保存全局事件、材料和关系；专题图保存关注范围、问题大纲、归集材料和研究证据。系统不会将用户描述直接写成已经发生的事实，也不会把共现的两个名字自动视为存在行动关系。

## 召回与判断

后台先通过实体和别名、动作关系以及扩展词项寻找候选，再让专题级模型判断相关性。当前未增加独立向量数据库或全量密集向量检索。

已配置FalkorDB时，全局事件图的有出处关系及个性化PageRank还会补充候选，最多扩展一跳、每轮30项；这些候选也必须经过模型判断。当前全局图分析窗口仍为最近最多5000个事件；历史回溯独立遍历本地已索引事件，不受该可视化/图分析窗口限制。所有回溯计数都不包含尚未投影为事件的原始GKG行。

| 结果 | 含义 |
| --- | --- |
| 核心进展 | 对关注事项有直接进展，归入专题材料 |
| 背景材料 | 有助于理解历史或上下文，作为背景归集 |
| 待核 | 信息不足、模型暂时不可用或证据校验未完成 |
| 不相关 | 已处理，但不符合专题范围 |

是否相关不等于事实已被证实。“官方否认某项行动”可能与专题高度相关，材料中仍保留其否认性质。判断使用固定版本的文章材料，记录原文出处；引用存在也不等于独立证实。

## 历史回溯与日常运行

保存专题后，后台分批处理已有事件，页面可以先使用。新到事件通过日常索引流程进入候选；历史任务有持久进度，服务重启后继续处理。页面中的回溯数量表示事件处理进度，不代表上游所有历史新闻已被采集，也不能证明某一时间段没有漏采。

人工加入或排除的事件不会被自动判断覆盖。专题定义改变后使用新版本处理材料，旧版本任务不能覆盖新范围。待核材料可以在模型恢复后重试。

范围改变后，旧自动判断立即从当前材料、时间线与研究取材视图隐藏，后台逐条重新判断，历史解释仍保留；人工选择继续生效。已归集材料可展开“查看收录依据”，读取具体文章版本、原文摘录和对应问题。历史回溯、文字解释及模型精筛各自运行，慢模型不会阻塞历史扫描；历史回填不触发实时新事件的自动补查。

描述解释与专题判断使用应用已有的模型连接配置。模型不可用时，页面应明确显示解释方式及待核状态。原始新闻和GKG档案不会因未归入专题或模型失败而删除。

后台模型调用与外部图操作均不应占用长SQL事务；历史回溯按批次提交，不在保存专题的HTTP请求中进行全量扫描。专题判断与采集策略中原有的领域筛选分别运行，后者不能代替专题相关性判断。

## 升级与迁移

已有专题保留原来的规则范围和人工操作。新版本增加专题定义、解释任务、历史进度及候选判断等独立表，不在旧Watch记录上追加必须手工迁移的字段。

需要切换到PostgreSQL时，使用 `news2douyin-migrate-sqlite`，停掉所有旧库写入进程，提供干净的一致SQLite快照，目标须为专用空库。新增专题表也参与逐表行数和全行哈希核验。完整步骤见[PostgreSQL运维说明](POSTGRES-OPERATIONS.md)与[SQLite迁移契约](SQLITE-MIGRATION-CONTRACT.md)。DuckDB、原始ZIP、作品文件和FalkorDB仍沿用原目录与配置；换主机需另行搬迁。
