# 0.24.0 发布说明

本版围绕事件雷达、新闻库和运行状态的SQL读取整理查询，减少为计数、分面和翻页装载完整文章及历史快照的工作，保留原有接收、不可变版本、图和专题流程。

- 统一数据库计数和窄列分页工具，状态页使用标量COUNT，正文留在需要查看原文时读取。
- 雷达SSR先返回预览列表、选题和翻页入口；浏览器独立调用 `GET /api/radar/facets` 加载精确统计，未完成显示统计中/…，失败可重试。
- 精确分面每次请求重新查询，无跨请求TTL缓存；后端继续合并统计、缩小聚合输入，减少历史版本临时聚合与CPU工作。
- 新增版本定位及文章来源、事件来源、雷达范围共四个读取索引，提供显式维护入口 `news2douyin-db-query-index`。
- 增加命名查询统计接口 `/api/database/queries`，观察当前进程的查询次数、耗时与错误，并零SQL读取数据库类型和连接池快照；不存储SQL参数、新闻原文和数据库凭证。
- 连接池容量与获取连接的等待分别设置；SQLite文件库默认5+10、busy30秒，PG保持8+8，两者池等待默认10秒。
- 提供[查询性能运维说明](QUERY-PERFORMANCE.md)，区分池等待、数据库锁等待和语句执行时间。

0.23用户停止服务并备份后，安装0.24，继续沿用原数据库连接、`storage_root` 和图命名空间。已有SQLite库保持兼容；切换到PG仍须另行执行已提供的停源迁移流程。升级不会自动删除原档、历史正文、版本、接收回执或作品，也没有访问或修改现场27GB数据库。

新建库和完整迁移的目标库按metadata建立四个读取索引；已有数据库普通启动不自动扫描或补建。工具默认只输出plan且不连接数据库，`--apply` 才显式执行：SQLite须停写维护窗口，PG使用 `CREATE INDEX CONCURRENTLY`。建议在评估备份、空间和维护窗口后使用 `news2douyin-db-query-index --apply --analyze`：SQLite仅分析四个索引，PG分析四张对应表；不加 `--apply` 的 `--analyze` 仍只输出plan。缺少统计可能使规划器不选覆盖索引。正常启动不自动ANALYZE，工具不删除或修复既有索引；列、部分索引等定义冲突会拒绝，PG invalid索引须人工复查。索引名称、列顺序及步骤见[读取索引维护](QUERY-PERFORMANCE.md#已有数据库的读取索引)。

精确统计没有完成时不会显示假0，预览行数也不代表全范围总数。首屏可用与统计全部就绪分别报告；SQL观测的cursor时间不包括fetch、ORM、HTML和浏览器处理。将统计移到独立请求会改变首屏工作量，不能直接把首屏耗时比值称为SQL总加速。完整读取契约见[两阶段雷达读取](QUERY-PERFORMANCE.md#雷达分两阶段读取)。

56万条、约9.3GB合成库中，默认雷达HTTP响应从同步完整页36.650秒变为列表预览1.394秒；精确统计另需独立请求7.173秒。首屏工作量不同，不将比值称作SQL总加速。完整报告及限制见[验证记录](validation/0.24.0/README.md)，安装后检查见release-0.24.0/VALIDATION.txt。未测现场27GB库，也不将夹具建索引耗时当作现场预期。
