## 本版重点检查

- 发生日期可与报道日期不同；未知时间不填猜测日期；无效日期、倒置区间和缺失的争议说明被拒绝。
- 节点必须绑定当前专题中的文章版本，摘录必须是原文连续片段，版本指纹必须匹配。
- 原文更新后，节点仍引用旧版本；导出包含被引用旧版本和当前版本正文。
- 来源被引用时阻止移除；删除节点后可移除关联，原文章、文章版本、历史脚本与删除记录保留。
- 人工标题与摘要不会被后续报道更新覆盖；全文检索能找到人工标题。
- 同时编辑同一专题时只接受一个基于旧版本的更新，另一个收到冲突提示。
- 拆分跨组证据节点会阻止执行；仅引用被选报道的节点随专题移动。
- 合并共享报道不会重复关联，节点保留，原专题归档，历史脚本保持原引用。
- 背景关系方向在两侧正确显示；目标专题合并后仍可解析关联。
- 外部检索只保存候选；选中后才入库。重复收录幂等，已有正文不被旧候选覆盖，来源记录能回到检索条件。
- HTTP 契约检查了关键词、日期边界、国家、数量、`x-api-key` 请求头、超时设置、错误提示与内容规范化；输出不包含 Key。
- 策略关键词模式使用选择日期，随后执行原有筛选入库；不会误走热门榜接口。

## 安装及升级

wheel 安装到独立 Python 环境，以 `python -I` 执行工具，确保实际使用安装资源。报告见 `validation-0.8.0/wheel-legacy.json`、`wheel-daily.json`、`wheel-management.json`、`wheel-events.json`。

升级样例由**安装的 0.7.0 wheel** 创建，包括停用的策略、暂停的计划、完成的正式采集和试跑、新闻、文章版本、每日选题及已生成脚本。安装 0.8.0 后继续使用原数据库与运行目录，验证上述数据及状态保留；原事件可以新增带证据的节点，之前生成的脚本内容完全不变。

复现升级：在 0.7.0 环境运行 `python -I tools/seed_upgrade_0_7.py /path/to/new-fixture`，再在 0.8.0 环境运行 `python -I tools/smoke_events_installed.py --upgrade-fixture /path/to/new-fixture`。目标目录须事先不存在。

## 未覆盖范围

未验证真实新闻源的账户权限、额度、覆盖率、返回质量和日期归属；这些需在实际环境试跑。没有事实真实性或事件语义归并准确率评测；节点由用户整理。没有 PostgreSQL 测试、多日驻留测试或浏览器兼容性矩阵。独立 RunDesk 应用未修改。

补充检索为有超时的请求，不使用持久任务队列；若进程在请求中停止，应重新检索。合并没有整次一键撤销，历史记录用于追溯或手动重新整理。详见发布说明中的功能边界。
