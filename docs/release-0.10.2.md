# 0.10.2：任务中心与排队状态

此前后台任务页仅显示最近 100 条记录，没有查找条件，也看不到为什么仍在等待。本版新增任务中心和单任务队列状态，便于日常查看采集、脚本及视频的执行进度。

## 任务中心

从页脚或运行管理进入“任务中心”，路径为 `/tasks`。

- 顶部统计全部任务、进行中、排队、失败与完成数量。这些是全库统计，不随下方筛选变化；点击卡片进入对应状态。
- “当前执行”显示当前服务的执行器状态及最多 5 项执行记录。多个服务实例共用数据库时，可能同时有多项执行记录。
- 可按标题/策略名/任务编号、任务类型、状态、首次提交日期及 IANA 时区筛选。日期结束边界包含当天，默认时区沿用系统设置，通常为 Asia/Shanghai。
- 支持分页，不再受“最近 100 条”的展示上限限制；筛选和页码保存在 URL，刷新和浏览器返回后保持。
- 选择“排队中”时按本轮入队顺序排列；其他查询按首次提交时间倒序排列。同一时间的任务使用编号保持稳定顺序。
- 每项可进入进度；失败项显示错误摘要并链接到处理页；已生成的脚本可直接打开，视频可进入产物页，采集可进入选题与诊断。
- 每 5 秒自动刷新，可以暂停或手动刷新。请求失败时保留已显示记录，并提示它们来自上一次成功刷新。

## 排队与耗时

单任务页新增“排队与耗时”，在执行期间约每 3 秒更新。位置按**全部等待任务**计算，即使列表只筛选视频或脚本，也不会重新编号；正在执行的任务另外计数。取消或重试会反映到位置中，已完成任务不再占队列。

| 显示项 | 含义 |
|---|---|
| 本轮排队 | 从最近一次入队到当前的等待时间；重试或恢复重新入队后重新计算 |
| 本次执行 | 当前这一轮从开始执行到现在的时间；仅对执行中或正在取消的任务显示 |
| 提交至结束 | 从首次提交到最终记录的结束时间，包含排队、执行、失败后等待和重试；不是累计计算耗时 |

旧记录缺少时间时显示“时间未知”。时间戳精度和设备时钟会影响秒数；不提供预计完成时间。排序位置是读取时的状态，多实例认领、取消和重试都可能改变它。

“当前服务执行器已停止”只描述本次访问的服务实例，不代表其他实例已经停止。数据库仍有有效执行记录时页面会提示可能由其他实例处理；执行状态已经过期时提示等待恢复。打开监控页不会触发任务恢复、重试或改变顺序。

## 保留的执行规则

每个服务执行器仍一次处理一个任务，多个实例可通过既有租约共同处理。没有增加优先级、插队、抢占、并发池或自动重试。长时间模型请求或视频编码仍可能让后续任务等待。取消与重试使用原有接口及检查点规则，旧输入、选题、稿件与作品不改写。

## 接口

- `GET /api/task-queue`：分页结果及全局概览。参数为 `query`、`kind`、`status`、`date_from`、`date_to`、`timezone`、`offset`、`limit`，每页 1–100 条。
- `kind`：`all`、`collect`、`trial`、`daily_script`、`script`、`video`。
- `status`：`all`、`active`（含排队）、`queued`、`running`、`cancel_requested`、`failed`、`succeeded`、`cancelled`。
- `GET /api/tasks/{task_id}/queue-status`：单任务全局队列位置、耗时、结果入口与执行概览。

结果包含 `task`、`queue_position`、`timing` 和入口链接；全局概览为 `summary`。查询不返回任务固定输入、模型/新闻密钥、请求指纹或执行器租约令牌。旧 `/api/tasks` 保持数组结构，旧 `/api/tasks/{task_id}` 和 SSE 结构保持不变。

SQLite 下每次查询在一个短只读事务内取得统计、排序与记录。队列位置先计算再筛选和分页，避免仅看到一部分记录时误报位置。监控不会逐个读取视频文件或计算媒体哈希。

## 升级

停止旧服务，备份数据库、运行目录和 `.env`。安装 `release/news2douyin-0.10.2-py3-none-any.whl`，或在源码目录执行 `pip install -e .`，继续使用原数据库与运行目录启动。

本版不新增数据库表或迁移任务记录，不新增必需依赖。先前的采集策略、定时计划、每日选择、草稿、作品及任务历史继续使用。
