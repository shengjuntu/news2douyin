# NewsNow关注议题：数据、指标与候选关系

这条链路服务于“从大量消息中挑出值得研究的视频题材”。中文平台关注回答本站采样中什么正在被关注；GDELT来源事件回答官方编码记录中哪些主体、行为和地点可能相关。用户选择后再补原文、交叉核查和深度研究，最后沿原有内容任务完成创作与作品。它们不是事实认证或全网受众统计。

## 操作和读取边界

在现有NewsNow采集策略中选择来源，试跑检查连接，正式采集后进入事件雷达的中文平台关注视图。可以按关键词、时间、关注分、升位和专题范围筛选；展开议题查看成员标题、来源链接、所见位置、时间轨迹与匹配依据。选择一个具体议题形成内容任务后，先补原文或进入研究。

关注议题使用所选来源的完整快照计算。采集策略中用于新闻库文章的关键词过滤和`max_items`不会删减这份观察输入；需要缩小关注视图时，使用雷达的关键词、时间或专题范围过滤。默认关注排序先按合格中文热榜平台覆盖数，再按榜位归一分均值，覆盖数和分数分别展示。

主菜单维持事件雷达、我的专题、内容工作台、新闻库。采集和后台诊断继续放在运行管理。网页/API只读取有上限的SQL摘要；不会在请求内打开观察DuckDB、全扫ZIP/JSON原档、调用LLM或等图写入。列表使用当前页与“还有更多”的有界读取，不为了显示总页数扫描全部观察。

## 三层状态与原始输入

| 保存位置 | 保存内容 | 用途与边界 |
| --- | --- | --- |
| `storage_root/newsnow/snapshots/`及各轮清单 | 内容寻址的完整响应、原始状态、校验和及观察引用 | 重放输入；标题、摘要不等于原文证据 |
| `storage_root/newsnow/attention.duckdb` | 唯一内容、来源条目、成功/空榜/失败观察、清单回执 | 派生观察历史；后台单进程所有权与线程锁保护 |
| PostgreSQL attention表 | Inbox租约、当前议题与成员、当前指标/小型曲线、候选关系、选题冻结快照 | 小型事务状态与Web读取；SQLite保留轻量兼容 |
| 既有FalkorDB `active_global` | `AttentionTopic`、有界成员、官方来源事件和候选边 | 可重建导航投影；不新增第五张图，不替换原本地事件事实 |

正式采集将清单引用放入持久队列。后台先验证清单和响应哈希，在DuckDB幂等记录观察，再在短SQL事务发布归并和指标；SQL发布失败可以用原清单重放。原始归档路径必须留在原`storage_root`内。DuckDB或图不可用时保留错误和积压，HTTP读取不接管后台重建。

旧正式采集通过`RunRecord`主键游标分批发现；试跑、仍在运行的记录不用于发布。页游标和处理回执持久化，启动不扫描所有文章或加载所有原档。缺文件、坏校验不能拿当前网络响应代替历史输入。`POST /api/attention/rescan`重新发现已有清单，不删除已处理状态、不重新计算done清单。

## 具体议题如何归并

本版算法`attention-group-v1`是保守规则，不是LLM抽取或经过训练的语义聚类模型。候选范围以最近72小时为主，读取有界；规范化URL和高标题相似度可以支持归并，人物、动作、对象、数字、否定和计划/已发生表述用来防止误并。相同人物本身不足以把“特朗普加征关税”和“特朗普会晤某国领导人”并成一组；“宣布实施”和“否认实施”也不应靠相似词吞并。

每个成员保留分组方法和依据。来源标题有歧义、缺少上下文或词表没覆盖时，系统倾向保留多个议题；“没有合并”不等于“确认是不同事实”。归并生成版本用于拒绝过时发布，完全相同的输入重放不制造新版本。它不把标题词项直接当作抽取已核实的人物关系。

## 关注分与升位分

原始平台有各自不同的热度字段和量纲，本版保留原值展示，不将字符串热度直接跨平台相加。列表位置是响应数组中的位置，页面称为“所见位置”；除非来源契约另有证据，不声称它就是官方排名。

| 指标/状态 | 当前定义 | 不能据此推出 |
| --- | --- | --- |
| 所见位置 | 条目在该次来源响应中的数组位置，从1开始 | 官方名次、真实曝光人数 |
| 关注分 | 已识别中文`hottest`来源内，按列表长度归一化位置；每个平台只取最好值，再平均 | 阅读量、播放量、全网热度 |
| 平台覆盖 | 最近6小时有效观察中出现该议题的合格平台数；别名归一，不重复计权 | 中国全体公众关注比例 |
| 升位分 | 同源、同一条目两次可比观察的位置差，按列表长度归一化；每平台取一值后平均 | 增长率、每小时速度、因果影响 |
| 历史不足 | 首次出现、前次没返回、来源失败、缺少可比条目或过期 | 0增长、0关注 |
| 缓存/内容不变 | 保留本地重复观察与上游状态，内容不变的可比位置变化记0 | 已确认持续真实上榜、上游确实重新抓取 |

对于长度`N>1`的列表，位置`p`归一化值为`100×(N−p)/(N−1)`；单条列表取100。升位分使用`100×(p前−p现)/max(1,max(N前,N现)−1)`。两个分数是位置代理值，不是概率。短榜与长榜的语义仍可能不同，界面同时展示原位置和来源列表长度，不能只看一个分数。

只有已识别的中文平台热榜进入上述关注/升位指标。`realtime`快讯、股票/非新闻榜、全球技术社区榜、自定义未知源不冒充中文大众热度。新平台首次出现增加的覆盖与原平台内升位分开；不同条目不能继承彼此的排名。来源失败、空榜和未尝试各自保留，不按零热度补齐。曲线为有上限的观察采样，完整观察仍在DuckDB；样本间不推定连续状态。

本地观察时间、NewsNow的`updatedTime`报告时间、条目自身的发布时间分开。报告时间不保证等于上游实际抓取时间；缺发布时间保持未知。重复缓存可以证明本站又看到了同一响应，不能证明平台的真实持续在榜时长。

采集停止后，网页仍只读SQL摘要，但会按当前时间将超过6小时的观察标为过期：当前分数变为未知，“正在升温”不再选入旧信号。历史散点和来源记录继续保留，这不表示关注降为零。

## GDELT候选与专题范围

关联对象是`OfficialEvent`和`OfficialMention`，不是本系统选定题材后构造的研究`Event`。本轮匹配只读取有限近期来源记录：默认最近7天观察窗口、最多200条Events、最多1000条关联Mentions、最多12个成员进行匹配、最多12个事件候选；专题范围最多读取200个专题并保留12个召回。达到上限会在匹配范围中说明，有界未命中不表示全库无匹配。旧闻最近又被观察到，也不能仅凭`last_seen`当成新事件。

候选方法包括同文档`source_url`、Mentions文档链接，以及主体、宽泛CAMEO行为加地区或明确日期等结构条件。同一文章可以提及多个官方事件，因此同URL也只能证明报道相关。纯结构规则不会单凭人物名确认身份；明显否定、未证实和具体数值未核验等情况会限制语义匹配。匹配分仅用于规则排序，含义为`rule_score_not_probability`。

状态分为`candidate`、`confirmed`、`rejected`。人工决定保留，后续同候选的新证据不静默推翻决定；未再次召回的旧版本决定可以保留历史，但不作为当前活跃关联。确认说的是“用户认可这个关联”，不认证报道真实性。匹配依据和未匹配原因应与分数同时查看。

专题关联是`keyword_recall`：以专题范围、维度、排除词和当前版本判断，遵守回收站墓碑。它不生成`WatchEvent`、正式材料会员关系或自动研究任务；暂停专题也不因这条关联重新启用。用户仍在原专题和内容工作台决定接受哪些材料。

## 图投影契约

所有新标签位于现有全局图，使用稳定键和参数化Cypher。后台仅补建`AttentionTopic.key`、`AttentionSourceItem.key`、`SourceEvent.key`范围索引，不复制到各专题图，也不阻塞HTTP启动。

| 节点/边 | 主要字段 | 语义 |
| --- | --- | --- |
| `AttentionTopic` | `key,title,score,score_known,rise_score,rise_known,generation,first_seen,last_seen,baseline_state` | 最新具体议题与位置代理值；未知分数无数值属性且`known=false`；时间为本地观察 |
| `AttentionSourceItem` | `key,item_key,topic_key,source_id,platform,source_kind,audience_scope,title,excerpt,url,snapshot_ref_json` | 原始榜单线索；图键按议题隔离，摘要不是正文证据 |
| `SourceEvent` | `key='gdelt/'+ID,provider='gdelt',external_id,event_date,actor1_name,actor2_name,event_code,action_place,source_url` | 官方来源事件身份；仅真实存在的SQL记录可投影，与`Event`分开 |
| `OBSERVED_ITEM` | `projection_owner,stamp` | 议题包含的有界线索成员 |
| `CANDIDATE_MATCH` | `status,active,method,score,score_kind,reasons_json,generation` | 官方事件候选、人工决定和当前版本状态；事实判断独立 |
| `CANDIDATE_FOCUS` | `status,active,scope_version,method='keyword_recall',reasons_json` | 专题范围召回；不等于已归集到专题 |

每议题图中最多保留最近30个成员、30条事件关联、30条专题召回。它是导航投影，不是完整历史；超出范围的数据在SQL/观察档案另有保存。缺少议题时只清理本投影所属的议题和派生成员，不删除共享`SourceEvent`或`Focus`。拒绝事件关系可保留历史状态，但`active=false`；旧版本关系也不活跃。

专题删除或版本变化时，Watch投影先更新Focus的`attention_scope_version`和`attention_recall_visible`，立即隐藏旧范围，再有界标记旧边。读取活跃范围关联必须同时检查：`r.active=true`、`f.attention_recall_visible=true`、`r.scope_version=f.attention_scope_version`、`coalesce(f.archived,false)=false`。只看边上的`active`不够。后续议题刷新移除不在当前有界召回中的旧边；attention投影不修改Focus的`archived/enabled`状态，不创建缺失Focus占位。

队列采用`GraphPending`原有token fencing：图I/O只能确认开始时捕获的token，期间到达的新更新仍待处理。event/watch/attention有独立游标与优先轮，持续更新的大事件不能让关注议题永久饥饿。

## 状态接口与运维

- `GET /api/attention/topics`：有界议题列表，支持关键词、时间、排序和专题范围。
- `GET /api/attention/topics/{key}`：成员、观察曲线、候选事件与依据。
- `POST /api/attention/matches/{key}`：明确确认、排除或恢复候选；更新图队列。
- `POST /api/attention/topics/{key}/select`：冻结本次线索和判断，幂等创建原有内容任务，不伪造全文/本地事件。
- `GET /api/attention/status`：后台状态、有限积压、最近处理、回填断点和错误。
- `POST /api/attention/rescan`：重新发现旧正式快照；不删除done回执、不强制重算。

默认开启`NEWS2DOUYIN_ATTENTION_ENABLED=1`。单个应用进程管理本地DuckDB；不要让多个服务副本共享同一个目录写入。备份必须保留完整`storage_root`，仅备份PG不能恢复观察输入。派生worker暂停不等于全应用停写；本版不自动清理历史数据或原档，也不替用户部署。
