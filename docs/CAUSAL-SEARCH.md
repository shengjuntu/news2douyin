# 查找前因

在事件雷达打开「查找前因」，输入一段事件描述，或从已整理事件的详情页带入标题和摘要。在「事件时间与搜索方式」可指定发生时间和自动追查。文字中只有一个明确日期时，系统可识别日期。日期按系统时区解释。同一天但无法确定先后时，线索会标为待核对。每条结果保留可核对的发生时间、来源公开时间和原文摘录。

手动查找先给一层候选，可沿任意线索往前查。选择自动追查时，系统按归因模型的证据排序，最多沿三个有较早公开证据的分支再查一层。候选解释保存在本次调查。可以回到同一调查继续追或重新查找，模型分数仅用于排序。

## 检索和补采

本地检索使用已整理事件、已入库的报道，以及能关联本地报道或出版者快照的 GDELT 编码线索。检索窗口上限为目标时间之前 90 天。没有向量服务时仍可用本地关键词检索。调查和待处理任务存入现有关系库，任务运行时释放数据库连接。

可从同一调查提交指定北京时间日期的 GDELT 补采。沿用「日报管理」的历史补采和重试队列，补采可取得上游仍提供的原始批次。补采及本地投影完成后，在调查中重新查相应分支。需要额外来源时，可以从结果事件进入已有的深度研究流程。

## 归因模型和调用接口

设置 `NEWS2DOUYIN_ATTRIBUTION_BASE_URL`、`NEWS2DOUYIN_ATTRIBUTION_MODEL` 和所需的 `NEWS2DOUYIN_ATTRIBUTION_API_KEY` 后重启应用。在 `/setup` 可核对服务公布的模型名称。使用归因模型生成检索问题和排序，另外用 `EMBEDDING_*` 配置向量召回。

- `POST /api/causal/investigations` 提交 `{"text":"一段事件描述"}`，可附 `event_at`、`event_key` 和 `automatic`。响应返回调查 ID 和队列状态。
- `GET /api/causal/investigations/{key}` 读取已保存的结果树。
- `POST /api/causal/investigations/{key}/expand` 提交 `{"node_key":"..."}`，沿所选节点继续查。提交已查过的节点可更新线索。
- `POST /api/causal/investigations/{key}/archive` 提交 `{"day":"YYYY-MM-DD"}`，发起现有的日度补采任务，任务状态显示在该调查里。
