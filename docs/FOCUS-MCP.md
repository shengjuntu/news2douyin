# 焦点与 Agent 接入

## 日常浏览

在一个焦点里选择「事件」「候选报道」或「档案」。事件页可按日期和分支浏览，档案保留时间线、关系图、已有研究记录和综述证据。新建焦点时先预览本地规则，再确认关注词、名称和范围。升级后，已有焦点继续按其已保存的跟踪方式运行。主动编辑并保存范围时，后台按新版本重新检查自动归集项，人工加入和排除继续有效。

## 连接

1. 在 news2douyin 的运行环境或 `.env` 设置独立的 `NEWS2DOUYIN_FOCUS_MCP_TOKEN`，然后重启 news2douyin。留空时端点未启用。
2. 在 Agent 里添加 Streamable HTTP MCP，地址是 Agent 所在机器可访问的 `https://你的服务器/mcp/focus`。需要本机或内网 HTTP 时，填实际地址和端口。鉴权使用 `Authorization: Bearer <同一个令牌>`。正式远程接入使用 HTTPS。
3. 打开焦点的「档案 → 连接 Agent」，可查看 MCP 地址和焦点编号。在 Agent 中也可按名称查找焦点。

下面的 Codex 配置从 **Codex 进程的环境变量**读取访问令牌。把服务端同一个值放进该环境变量，按现有方式管理密钥即可。一个实例的令牌可读这个实例中保存的焦点。研究用的 `/mcp/research` 使用各自的既有配置。 [Codex MCP 配置](https://developers.openai.com/codex/mcp)

```toml
[mcp_servers.news2douyin_focus]
url = "https://news.example.com/mcp/focus"
bearer_token_env_var = "NEWS2DOUYIN_FOCUS_MCP_TOKEN"
```

## Agent 可以读取什么

| 工具 | 用途 |
| --- | --- |
| `focus_list` | 按名称查可访问的焦点及其编号 |
| `focus_overview` | 查询筛选范围内的事件总数，并按日期、国家、事件分类或焦点分支分组 |
| `focus_list_events` | 用同一套筛选条件分页读取已收录事件 |
| `focus_get_event` | 读取某个收录事件的日期、地区依据、关联报道和可读的来源版本 |
| `focus_read_source` | 按来源编号和版本分页读取本地保存的文字 |

一个问法是「查找特朗普焦点，给我过去七个北京时间日里与日本有关的经济进展。先看地区角色和已有分类，把同一件事的多篇报道归在一起，重要判断给出原文和版本。」先用 `focus_overview` 了解可用分组，再缩小范围分页读事件。用相同筛选条件继续读取 `next_cursor`。

日期可选 `observed`（最新已索引材料的北京时间日）或 `occurred`（最早的已核对发生日）。国家筛选使用两位 ISO 代码，地区数据分为有出处的行动地、影响地、GKG 提及地和报道国家。国家计数按事件去重，同一事件可能属于多个国家。事件分类来自已保存的主题字段，空值会显示为未分类。它与焦点分支分别统计。

这些工具只读本地收录和已保存的来源版本。可取得的内容取决于原来保存的是全文、摘录还是只有标题。Agent 决定如何归类、翻译或生成简报，服务返回数据与来源。事件列表每页最多 100 项，来源列表每次最多 50 项，来源文字每次最多 10,000 字符。读取实时索引时，新收录和更新会影响后续页，复查历史时可以指定明确的日期区间。
