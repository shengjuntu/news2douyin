# 焦点与 Agent 接入

## 日常浏览

在一个焦点里选择「事件」「候选报道」或「档案」。事件页可按日期和分支浏览，档案保留时间线、关系图、已有研究记录和综述证据。新建焦点时先预览本地规则，再确认关注词、名称和范围。升级后，已有焦点继续按其已保存的跟踪方式运行。主动编辑并保存范围时，后台按新版本重新检查自动归集项，人工加入和排除继续有效。

## 持续研究

从事件雷达进入已有焦点，或者先将感兴趣的事件加入焦点。打开焦点页的「持续研究」，填写要长期跟踪的问题，再点「开启持续研究」。例如可以写「跟踪这项关税的正式公告、生效日期、豁免范围和首期进口数据」。已有焦点在升级后按各自的原设置运行，持续研究需要逐个开启。

首次使用前，在「研究助手设置」确认现有 RunDesk/Codex 环境能运行新闻研究，且能访问本服务的研究 MCP。默认由 News2douyin 本地安排复查。原文、事件和每轮调查记录保存在 News2douyin，每轮调查通过同一个应用绑定提交。研究过程可在该轮的独立记录中查看。[研究环境设置](DOCKER-RESEARCH.md)

| 触发条件 | 专题中的结果 |
| --- | --- |
| 首次开启 | 结合研究目标和近期可用的焦点材料开展首轮调查。 |
| 出现新材料 | 后台检查已收录事件的报道与焦点候选线索。可识别的相同内容合并处理。只有实际核实的判断变化才更新当前判断。 |
| 待查问题到期 | 即使这段时间没有新增报道，也会带上上次判断和待查问题进行复查。 |
| 手动复查 | 点击「立即复查」。已有调查进行时可直接查看进度。 |

专题页可以查看当前判断、原文引文和下次复查的问题。展开「历次研究」可对照之前的判断、触发原因与该轮记录。搜索命中和转载可以用来找线索，判断更新需要关联已核对的原文。复查日期按北京时间显示。

在「调整研究目标」中可以暂停或修改目标。暂停后停止后续调度；已经提交到 RunDesk 的任务可从对应研究记录查看。修改目标后会围绕新目标重新建立判断，旧轮次保留在历史中。同一焦点开启持续研究后，自动定向补查交由这个流程安排，人工发起的专项核查仍可独立执行。

使用本地调度时，News2douyin 后台服务需要运行才能按时复查。服务重启后会从数据库接续轮次并处理已到期问题。如果显示调查失败，请查看本轮错误和「研究助手设置」，恢复连接后可点「立即复查」重试。

### 将一个专题交给 RunDesk Bot

1. 先升级 RunDesk 到 0.76.0，再升级 News2douyin 到 0.65.0。在「研究助手设置」确认应用绑定可用，检查一个普通研究任务能否访问研究 MCP 和 Codex。
2. 打开专题的「持续研究 → 调整研究目标」（新专题显示「设置研究目标」）。在「由谁安排调查」中选「RunDesk Bot」并保存。已有持续研究轮次正在执行时，等本轮结束再移交。已有专题默认沿用本地调度。
3. 移交会带入已有判断、证据及待查问题。同步过程可在专题页查看，运行中可在 RunDesk 的「任务」页检查 Bot 的使命、各个待查问题与下一步行动。
4. 要交回时，选择「News2douyin 本地调度」并保存。新闻服务等 RunDesk 确认暂停后再恢复本地派发。连接中断时可在专题页查看移交进度，修复原绑定后由后台继续同步。

首次移交会检查宿主版本、应用权限和工作区绑定。本机 Codex 模式沿用研究助手的管理员连接，Docker 模式可使用具有新闻应用读取和运行权限的应用凭证。要更换 RunDesk 地址，先将已托管的专题交回本地并等待确认。同一地址的失效令牌可直接在研究助手设置中更新。

RunDesk 可以在新闻服务离线时为到期的问题登记行动，恢复连接后才开始补看或研究。新闻适配器对覆盖范围的说明仅指本地收录材料。到期问题第一次补看后若覆盖仍不足，RunDesk 等待一小时，再派一次调查去核查来源。需要确认正式发布、延期或撤回时，可打开研究轮次查看所引用的原文。管理员在 RunDesk 任务页调整提醒偏好后，Bot 仍会按已保存的议程继续复查。

## 连接

1. 在 news2douyin 的运行环境或 `.env` 设置独立的 `NEWS2DOUYIN_FOCUS_MCP_TOKEN`，然后重启 news2douyin。留空时端点未启用。
2. 在 Agent 里添加 Streamable HTTP MCP，地址是 Agent 所在机器可访问的 `https://你的服务器/mcp/focus`。需要本机或内网 HTTP 时，填实际地址和端口。鉴权使用 `Authorization: Bearer <同一个令牌>`。正式远程接入使用 HTTPS。
3. 打开焦点的「档案 → 连接 Agent」，可查看 MCP 地址和焦点编号。在 Agent 中也可按名称查找焦点。

下面的 Codex 配置从 **Codex 进程的环境变量**读取访问令牌。把服务端同一个值放进该环境变量，按现有方式管理密钥即可。一个实例的令牌可读这个实例中保存的焦点。研究用的 `/mcp/research` 使用各自的既有配置。 [Codex MCP 配置](https://developers.openai.com/codex/mcp)

```toml
[mcp_servers.news2douyin_focus]
url = "https://news.example.com/mcp/focus"
bearer_token_env_var = "NEWS2DOUYIN_FOCUS_MCP_TOKEN"
```

## Agent 可以读取什么

| 工具 | 用途 |
| --- | --- |
| `focus_list` | 按名称查可访问的焦点及其编号 |
| `focus_overview` | 查询筛选范围内的事件总数，并按日期、国家、事件分类或焦点分支分组 |
| `focus_list_events` | 用同一套筛选条件分页读取已收录事件 |
| `focus_get_event` | 读取某个收录事件的日期、地区依据、关联报道和可读的来源版本 |
| `focus_read_source` | 按来源编号和版本分页读取本地保存的文字 |

一个问法是「查找特朗普焦点，给我过去七个北京时间日里与日本有关的经济进展。先看地区角色和已有分类，把同一件事的多篇报道归在一起，重要判断给出原文和版本。」先用 `focus_overview` 了解可用分组，再缩小范围分页读事件。用相同筛选条件继续读取 `next_cursor`。

日期可选 `observed`（最新已索引材料的北京时间日）或 `occurred`（最早的已核对发生日）。国家筛选使用两位 ISO 代码，地区数据分为有出处的行动地、影响地、GKG 提及地和报道国家。国家计数按事件去重，同一事件可能属于多个国家。事件分类来自已保存的主题字段，空值会显示为未分类。它与焦点分支分别统计。

这些工具只读本地收录和已保存的来源版本。可取得的内容取决于原来保存的是全文、摘录还是只有标题。Agent 决定如何归类、翻译或生成简报，服务返回数据与来源。事件列表每页最多 100 项，来源列表每次最多 50 项，来源文字每次最多 10,000 字符。读取实时索引时，新收录和更新会影响后续页，复查历史时可以指定明确的日期区间。
