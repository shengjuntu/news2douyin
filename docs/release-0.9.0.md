# 0.9.0：有证据的脚本工作台

本版把事件专题中已核对的发展脉络接入脚本生成，保留“每日采集 → 勾选新闻 → 快速初稿”的既有入口。

## 使用流程

1. 打开事件专题，在“发展脉络”添加或编辑进展，确认时间含义、来源版本和摘录，勾选“已核对”。
2. 点击“根据已核对脉络生成脚本”，选择一个或多个节点。未核对的节点不可选。
3. 选择快讯、解释或事件复盘，目标时长 30 / 60 / 90 / 120 / 180 秒，以及客观播报、通俗讲解或审慎分析。
4. 选择“证据提纲”或“AI 有据初稿”，提交后台任务。可关闭网页，之后在脚本工作台或任务列表找回。
5. 打开结果逐段编辑：口播、事实/分析类型、引用节点与来源、分镜、素材需求。口播全文由分段同步组成，分析段自动加“分析：”。
6. 保存新版本，人工核对来源与内容，送审并通过后导出制作包或继续进入视频制作。

脚本工作台同时展示近期生成任务和稿件。任务失败时显示原因，可取消或重试。新提交生成独立草稿，既有稿件及其审核状态不会被覆盖。

## 两种生成方式

| 方式 | 能力与边界 |
|---|---|
| 证据提纲 | 无需模型；依据已核对节点组织标题、日期、说明、引用及素材提示。快讯按有日期节点倒序、未知时间放后；复盘按脉络顺序。不会自动补写因果解释或分析，需继续编辑。 |
| AI 有据初稿 | 将所选节点、明确时间、不确定性和摘录发送到已配置的兼容模型服务，按类型、风格和时长要求生成结构化草稿。输出须通过分段与引用校验。失败不自动替换为提纲。 |

模型继续使用 `.env` 的 `OPENAI_BASE_URL`、`OPENAI_API_KEY`、`MODEL`，不增加依赖。调用使用既有 `/chat/completions` 接口，连接超时 10 秒、读取超时 120 秒。模型需要能返回所要求的 JSON。真实调用可能产生费用，页面会说明所选资料的发送范围。

目标时长指导篇幅，不是硬性配音时长。编辑页给出每秒 3–4 个字符的粗估，含数字或外语时误差较大，以最终配音为准。提纲模式尤其不保证填满所选时长。

## 逐段证据与编辑

- 提交时固定事件版本、所选节点、来源文章版本、原文摘录与内容指纹；保留对应版本的完整原文供导出追溯。
- 每段至少对应一个节点及其来源编号，例如 E1、E2。只接受冻结快照内的编号，且引用须对应本段所选节点。正在被引用的报道不能从稿件来源中取消选择。
- 同一篇新闻的不同历史版本可以分别成为 E1、E2；不会把后来更正的正文偷偷替换进旧稿。
- 后续修改、删除或合并事件节点，不会改写已提交任务的输入。想使用新资料，需要重新提交任务。
- 段落可增删、排序；事实与分析分开标注，分镜及素材需求可编辑。现有版本冲突提示、本地副本、历史恢复和审核继续使用。
- 有据稿必须保留分段与引用；旧版平文脚本仍可按原方式编辑。要给旧稿加入新脉络，可从相应专题创建一份新稿。

**“已核对”、事实/分析标签和引用结构检查都不等于系统完成了事实核实。** 模型仍可能错误概括原文、误读时间、编造因果。编辑需要逐段对照来源核实；系统不会自动通过审核。模型提示会要求保留大致/有争议/未知时间，但语义正确性不能靠编号校验保证。

## 后台与恢复

- 使用已有持久队列、进度流、取消、重试和租约恢复机制；一次提交只对应一个任务和一份最终草稿。相同幂等键、相同参数返回原任务，不同参数返回冲突。
- 网络调用在数据库事务之外执行。有效结果先保存检查点；写文件或提交数据库前失败，重试可复用已验证结果。
- 草稿版本、任务结果和完成状态在同一事务中提交。取消、停止或失去租约的旧执行器不能提交晚到结果。
- 关闭网页不影响服务器执行；关闭服务器会暂停处理，重新启动后恢复。模型请求进行中时，取消需等待其返回或超时。
- 如果进程在模型返回之后、检查点保存之前退出，恢复可能再次调用模型并产生费用；不承诺外部请求只发送一次。
- API Key 不存入任务输入。模型地址和型号在提交时固定；执行时如发现当前地址或型号已改变，会提示恢复原配置或重新提交任务，避免把新地址的凭据发送到旧地址。已保存的合格结果不需要再次调用模型。

上限：一次 1–12 个节点、最多 20 个来源版本、30 个脚本段落；所选证据包不超过 2 MB，发送给模型的节点与摘录内容不超过 60,000 字符。超过时明确提示分批处理，不静默删减来源。不同模型的上下文上限不同，即使未达到本系统上限，也可能需要减少节点或摘录。

## 导出与视频衔接

已审核的制作包保留原有 `script.txt`、`script.json`、`revision.json`、`sources.json`、`script.md`、素材清单与校验清单，并为有据稿增加：

- `storyboard.json`：每段类型、口播、节点、来源编号、画面与素材需求。
- `evidence_snapshot.json`：固定的事件版本、节点、来源与历史原文。
- `script.md` 增加分段引用与分镜，素材清单增加结构化分镜。

平文 `script_text` 继续提供给现有配音与视频流程，分析标记包含在口播中。素材需求只是计划，不代表已获取图片、音频或授权；当前视频流程仍需自行准备或上传素材，并不会自动按新分镜检索素材或生成多个镜头。独立 RunDesk APP 本次未修改。

## 升级

1. 停止服务，备份原 `runs_v7` 数据库与整个运行目录，保留自己的 `.env`。
2. 解压本包，在原环境运行 `pip install -e .`，或 `pip install release/news2douyin-0.9.0-py3-none-any.whl`。
3. 使用原数据库和运行目录启动 `news2douyin-server --host 127.0.0.1 --port 18080`。
4. 打开原事件专题，确认已核对节点存在，再创建一份有据稿。

数据库只新增 `ScriptGeneration` 表，既有脚本快照不会批量重写。0.8 → 0.9 的安装升级已使用真实旧 wheel 创建的数据库验证。默认目录沿用 `runs_v7`；如以前指定了其他 `--db-url` 或 `--storage-root`，继续使用原参数。不要删掉存放历史脚本、导出和视频的目录。

## 新接口

- `POST /api/events/{event_key}/script-tasks`：提交；包含 `expected_version`、`moment_keys`、`options`、`idempotency_key`，返回 202 和任务位置。
- `GET /api/script-tasks?event_key=...`：查询近期脚本任务。
- `GET /api/script-tasks/{task_id}`：输入摘要、进度、生成结果链接。
- 取消/重试继续使用 `/api/tasks/{task_id}/cancel`、`/retry`。
- 脚本编辑继续使用 `/api/scripts/{package_key}`，`document.segments` 为新增可选字段。有据稿不可清空。

`options`：`mode=brief|explain|recap`，`style=neutral|plain|analytical`，`duration_sec=30|60|90|120|180`，`backend=outline|llm`。
