# 每日事件雷达

## v0.35 的阅读与补采

今天可按已收到的材料多次生成。选择国家、类别或数据来源分组，用序号记住位置，点外语卡片上的「译成中文」查看译文。历史缺期与缺批在「日报管理」处理。[操作说明](DAILY-OPERATIONS.md)

同日两批真实 GKG 的第 2 版保留了第 1 版的 40 条，新增 60 条；同一套后台流程也完成了用归档补回历史日报的实测。[当天样本](validation/0.35.0/public-samples.json) · [历史补采](validation/0.35.0/backfill-sample.json) · [50 万行合成测试](validation/0.35.0/scale-500k.json)

## v0.34 的报道广度

同一标题组的报道先按现有规则归并，再计算用于排序的来源数。每个已核对的媒体集团计一组，未匹配名录的有效主机各计一组。这个数字用于估计传播广度。核实独立采编或事实仍须检查报道出处。域名样本与来源链接保留在卡片里，排序用的来源数超过 32 时，广度分封顶。[媒体名录和识别范围](PUBLISHER-BREADTH.md)

官方事件保留本期新增报道、域名和累计数量。历史覆盖完整时，出现本期首次提及的关联文档可获得至多一分时效加分。对于已报道过、此次只有报道数量增加且代表材料缺少行动表述的事件，该项为零。只有域名合计时，系统不会据此推算新增了多少媒体集团。已发布的历史卡片保留原有计数和排序说明。

## v0.33 的归组与阅读名额

新版在日报里合并可核对的标题写法。明确排版的通讯社署名可以省略；部分 iHeart 和 NBC 地区台的频道名还要与发布网站相符，且网页路径中的文章名须完整对应标题。正文式副标题、数据、方向、否定、日期和版本序号保留。部分带数字的英文法规标题可将同一时态的几种生效措辞归在一起。其他改写仍可能重复占位。每张卡保留来源原题、链接和归组后的域名数，最多列出八个来源样本。

对已有历史报道的 GDELT 官方编号，如果当天有新报道、历史计数完整，而代表材料中没有可识别的行动表述，卡片标明报道增加。这一情形使用原有传播广度分，不再因为新增域名额外加分。仅有 GKG 标题时，仍按可读材料筛选。已冻结的旧日报维持发布时的原貌，随后七天的候选会与旧日报保存的标题核对。

用连续三个日期、每日三个公开 GKG 批次回放，两个版本每天各读 100 条。3 月 16 日，美国空袭的同一篇稿件原占三席，合为一席后保留四个链接；有关加拿大关税谈判的同一篇稿件也从三席归为一席，保留三个链接。这一天收回四个可证实的转载重复名额，其他两天此规则未识别出旧榜的重复名额。这个样本没有给一般性的选题质量打分。具体日期、统计口径和每条链接见[归组验证记录](validation/0.33.0/headline-grouping.json)。本地日报评审见[按日核对选题](DAILY-REVIEW.md)。


v0.32 已增加官方报道计数、NGrams 证据和旧版选榜对照，参见[官方事件与补证](GDELT-EVIDENCE.md)。以下记录为 v0.31 的基础行为与基准。

目标是让一位编辑每天最多读 100 条，每条有可以打开的报道、入选理由和选题入口。页面展示一份稳定的日报。原始采集继续全量归档，实时线索仍可从同一页面进入。

## 使用

默认打开 `/radar` 阅读北京今天已收到的材料。今天可以反复生成，换版时仍能阅读原清单。可按日期回看、按国家或类别阅读，在「日报管理」检查历史缺期与采集缺口。[实时日报与历史补采](DAILY-OPERATIONS.md)

安装 0.31.0 后，CLI 和 Web 使用相同数据库、相同的采集目录。在网页上选择一个尚未生成的历史日期，点“生成这期日报”可交给同一个后台进程补建。服务运行时优先用此入口。CLI 适用于独占采集目录或离线副本。下面路径应指向正在使用的持久目录：

```bash
news2douyin-daily-radar build --day 2026-11-14 --storage-root runs_v7
news2douyin-daily-radar show --day 2026-11-14
```

`GET /api/radar/daily?day=2026-11-14` 返回生成状态、清单和计数。数据库第一次启动自动创建日报表。后台按北京时间生成当日版，收日后可生成完整日版。已发布的历史清单可以在补齐材料后明确发起重算。通过环境变量 `NEWS2DOUYIN_DIGEST_ENABLED=0` 可关闭自动生成。已有大型工作库可运行 `news2douyin-db-query-index --apply` 补建 `articleversion(observed_at,id)`。PostgreSQL 使用并发建索引，SQLite 在适合维护的时段执行。后台读取窄列后排序并原子发布，网页只读发布结果。保留上一日已发布内容，升级前建议备份事务库和采集目录。

## 解释结果

- GKG 的标题取自本地归档的原始网页标题。按原批次的本地入库时间计算归属日，补采旧批次可能带入较早的新闻。只有标题的条目保留原文入口。
- GDELT 官方事件的 CAMEO 编码和 Mentions 提供行动及关联文档线索，一篇文档可涉及多项行动。标题描述的是关联报道。只有类别与国家、没有可读报道的线索保留在实时浏览中。
- 本地事件沿用已经保存的报道及专题关联。全球标题匹配关注范围时，可作为“待核”的弱线索进入排序，与已归入专题的材料分开计权。中文平台上榜是注意力信号；缺少热榜观测不代表受众兴趣为零。域名数量只说明传播范围，同源转载可能跨多个域名。
- 首版采用可解释规则。排序会识别明确的政策阶段、影响线索，以及少量发布机构的正式文书路径；未登记的原始来源仍能凭其他信号入围。当前使用的归并和排序不需要模型调用，每次计算使用独占的临时磁盘文件，运行结束自动释放，不会向在线数据库写入这些中间数据。编辑规则榜没有用你的判断训练过。跨语言改写、同标题的不同进展、不同标题的同一事实仍会造成漏并或误并，盲评可以记录这些错误。工作库的旧版关联和热度字段缺乏完整历史时，历史重算有局限；冻结的日报保留发布当时的结果。
- 媒体首页偏好学习、对事件转折的跨语种语义识别，以及训练专属的中文视频选题模型，安排在获得真实人工评审后决策。

## 编辑回放

服务运行时，从包含事务库和 DuckDB 采集文件的一致副本回放，可避免多个进程争用在线 DuckDB 文件。使用同一段时间已经收集的材料，将三种榜单混排，让评审者先判断“应当知道”“愿意深研”“是否重复”。从各组榜外再抽样，找出所有算法一起漏掉的消息。评审前保留内部模式对照文件，评审者只看盲评文件。完整回放规则与参数以工具 `--help` 为准。

```bash
news2douyin-review export --start 2026-11-01 --end 2026-11-14 --out review --storage-root runs_v7 --warmup-days 7
news2douyin-review score review
```

本地回放只能比较已收集并接受评审的材料。若要测采集漏报，可另请编辑在看榜前写下每日必知事件，凭独立来源核实其是否进入原始归档、候选和最终百条。

## 早期版本的规模测试

在 100 个启用的专题下，对本地 DuckDB 已归档的 192 个合成 GKG 批次做了一次完整出刊。50 万行中有 5,000 行无效，另有 5,000 行缺标题。49 万条可读候选按标题归为 62,400 组，发布 100 条，其中 5 条命中专题提示。这组数据特意混合了大量转载与长尾标题；组数只代表此测试的标题分布。

| 测量范围 | 本次结果 |
| --- | ---: |
| DuckDB 扫描、专题匹配、归并、排序、PostgreSQL 16.2 发布 | 37.98 秒 |
| Python 进程峰值常驻内存 | 146.3 MiB |
| 排序临时盘占用，采样峰值 | 486.4 MiB |
| 发布后从 PostgreSQL 读取整期快照，单次 1 条 SQL | 5.73 毫秒 |

归并使用每次任务独占的临时 SQLite 文件，文件随任务结束删除。它只保存本次计算的中间数据。上表未计入网络采集、原始压缩包解码、生产库并发负载及 HTTP 耗时。内存数值只含 Python 进程。实际阅读价值需用前述编辑回放验证。

在有 `pgserver` 测试依赖和相应系统 locale 的环境可复跑：

```bash
python tools/benchmark_daily_radar.py --stage archive --rows 500000 --watches 100 --locale en_US.utf8
```


### 焦点归集与日报截止时间

评分和卡片中的焦点说明共用成员判断。自动归集需要有该版焦点在本期截止前的有效依据，人工归集按关联记录的时间判断。阅读已出版日报时使用该期保存的卡片与来源。主动重算历史日期时只采用能核对的关系，旧库缺少完整的规则版本生效区间，无法据此精确回放每个落选事件当年的归属。
