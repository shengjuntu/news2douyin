## 新增检查的重点

- 只接受当前专题的已核对节点，拒绝空选择、重复节点、失效节点和过期专题版本。
- 并发相同幂等提交只生成一个任务；换参数复用旧键会返回冲突。
- 快讯、解释、复盘均能创建独立版本化草稿；重新提交不改写旧稿。
- 同一篇报道的两个内容版本分别固定，后续删除节点不改变已提交任务的输入。
- 模型只收到所选节点与摘录；API Key 不入库。模型配置变更会阻止向旧地址发送新配置凭据。
- 拒绝不存在的来源/节点、空引用、重复段落标识、额外模型输出字段，以及引用与所选节点不对应的结果。
- 模型网络/格式失败有清楚的任务错误，不回显响应正文或密钥，不自动改成提纲。
- 写入中断后，数据库不留下半份草稿；文件清理后可从已验证检查点重试，无需再次调用模型。
- 取消任务后不接纳晚到结果；租约过期的执行器不能保存，恢复后沿用原证据快照。
- 编辑必须保持正文和分段一致，不能清空有据稿的引用结构；版本冲突、历史恢复、审核与导出保留。
- 制作包的分镜、素材需求、逐段编号和固定原文与审核版本一致，仍提供视频链路使用的平文口播。

这些检查验证结构和流程，不验证模型每句话是否被原文充分支持。事实核实仍需编辑完成。

## 安装和旧数据升级

将 release wheel 安装到独立环境，使用 `python -I` 确认执行的是安装后的包与模板。报告见 `validation-0.9.0/wheel-*.json`。

升级数据库由**安装的 0.8.0 wheel** 创建，包含原新闻、来源版本、每日选择、旧脚本、已核对事件节点、正式采集和试跑历史，以及已停用策略和暂停的日程。安装 0.9 后使用原数据库：旧脚本完整快照及节点保持相同；用旧节点成功生成新有据稿，来源指纹一致。另检查关闭并重新创建服务实例后，失败任务仍可重试并产出独立草稿。

复现：先在 0.8 环境运行 `python -I tools/seed_upgrade_0_8.py /path/to/new-fixture`，安装 0.9 后运行 `python -I tools/smoke_scripts_installed.py --upgrade-fixture /path/to/new-fixture`。
