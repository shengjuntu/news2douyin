## 新增的后端验证

- 试跑使用提交时的配置；之后编辑或停用策略不改变已入队任务。
- 试跑不创建文章、事件、采集观察记录或文章处理记录；导出失败后重试复用筛选检查点。
- 停用同时暂停计划，重新启用不会自动恢复计划；新任务受到状态检查，已有任务可继续。
- 删除关联策略有保护，删除后历史新闻、任务、试跑诊断保留；归档计划的编号不会被新计划复用。
- 调度器入队前重新核对当前计划，并按当前时区固化日期。
- Cron 数值、范围、步长、段数和时区验证；旧版日/星期 AND 语义；夏令时不存在与重复时间处理。
- AI 部分返回和调用失败的规则回退；原因总数等于输入总数；前 50 条明细上限。
- 零输入、来源全部拦截和相关性全部过滤分别诊断；无效配置和日期给出明确错误。
- 试跑取消、关联检查、API 参数校验与页面渲染。

两个旧调度测试的样例计划改为每分钟执行，触发时间改为明确的 ISO 时间；继续测试原有的原子提交和完成状态更新，适配本版新增的“确实到期才入队”检查。

## 安装与升级

wheel 在独立环境安装，以 `python -I` 执行检查，避免源目录掩盖安装资源问题。报告位于 `validation-0.7.0/wheel-legacy.json`、`wheel-daily.json`、`wheel-management.json`。

升级样例由安装的 **0.6.0 wheel** 创建，包含一条策略、一条计划、完成的采集任务、两篇新闻、每日选题及已生成脚本。替换安装为 0.7.0 后使用原数据库和运行目录，验证原对象编号、选题与脚本关系、来源及历史任务仍可读，旧策略默认为启用。没有逐项诊断的旧任务明确显示历史记录提示。

复现升级：先在 0.6.0 环境运行 `python -I tools/seed_upgrade_0_6.py /path/to/new-fixture`，再在 0.7.0 环境运行 `python -I tools/smoke_management_installed.py --upgrade-fixture /path/to/new-fixture`。

视频回归使用 FFmpeg、FFprobe 和本机中文字体（通过 `NEWS2DOUYIN_VIDEO_FONT` 指定），包含真实离线渲染；不表示真实配音服务可用。
