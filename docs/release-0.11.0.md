# 0.11.0：RunDesk 新闻研究

从新闻或事件发起持续研究。news2douyin 配置专用 RunDesk 实例、安装实例级研究 Skill 与 MCP；Codex 执行检索、阅读和多轮追问，通过 MCP 保存资料、判断和报告。RunDesk 代码不需要修改。

## 安装与升级

先停止旧 news2douyin 服务，备份原数据库及运行目录。在原虚拟环境中安装：

```bash
python -m pip install "./release/news2douyin-0.11.0-py3-none-any.whl[research]"
```

也可以从源码安装 `python -m pip install -e ".[research]"`。`research` 额外安装 pypdf，支持文字型 PDF；网页和本地新闻读取不依赖 pypdf。扫描件 OCR、付费墙与需要登录的网页不在本版范围。启动时继续使用原 `--db-url` 与 `--storage-root`。数据库只增加研究相关表，不改写原有新闻、事件和已审核稿。

```bash
news2douyin-server --host 127.0.0.1 --port 18080
```

沿用原项目 Python 3.10+、FastAPI + HTML 架构，无新增 Node 运行依赖；不安装 GPT Researcher。

## 首次配置

1. 启动 RunDesk v0.5.4 或接口兼容版本，确认其 Codex 可运行。RunDesk 演示模式不能执行真实研究。
2. 打开 `/research/settings`。填写 RunDesk 根地址和 Token；无 RunDesk 认证时 Token 可留空。
3. 填写回连地址，即 **Codex 所在机器能够访问的 news2douyin 根地址**。同机默认为 `http://127.0.0.1:18080`；跨机器使用实际可达地址或受保护的反向代理地址。遵循原应用的本地部署约束，不直接向不可信网络开放无认证的管理界面。
4. 选择 WorldNewsAPI（新闻检索）或 Tavily（通用背景资料检索），填写对应 API Key。也可在服务端设置 `API_KEY` 或 `TAVILY_API_KEY`。这些服务的可用性和费用由提供方账户决定。
5. 点击“配置研究助手”。应用创建自己的实例和托管工作区，写入 `scope=instance` 的 news-research Skill，并配置 HTTP MCP。重复操作复用已创建的实例、工作区，不替换无关 MCP。
6. 为页面显示的**专用实例配置目录**配置 Codex 模型与认证。它有独立 CODEX_HOME，不会自动复制默认实例的登录信息。可在服务器上使用该目录运行 Codex 的登录或模型配置流程。
7. 点击“检查连接”。该检查确认 RunDesk、实例认证状态和 MCP 工具发现，不调用模型，不代表研究质量已经验证。

配置会保存在运行目录的 `research/settings.json`，权限默认仅当前用户可读写（Windows 仍取决于目录 ACL）。保存 Token/API Key 时留空表示保留原值；切换 RunDesk 地址或搜索提供方时不沿用旧提供方凭据。配置页和 API 不回传密钥。MCP 使用独立 Bearer Token，浏览器通过应用后台调用 RunDesk，不接触该 Token。

## 日常操作

- 在每日选题、新闻库、新闻详情或事件专题点击“深入研究”。填写研究目的、策略、历史起点和资料截止时间；可立即启动或只保存课题。
- 工作台左侧显示问题，中间切换报告、证据与脉络、执行进度，右侧查看保存的原文段落。
- 运行中输入补充要求并点击“追加到当前研究”。RunDesk 接收成功与模型已经执行是不同状态；实际进展以问题、工具记录和新报告为准。
- Codex 等待审批或用户输入时，工作台提示到 RunDesk 处理，本版不会自动替用户批准。
- 停止后保留资料。继续研究会启动新的执行与会话，读取原课题的证据和报告；不依赖旧会话始终存活。
- 后续发生新进展时，可以勾选“将资料截止时间更新到现在”再继续。旧报告保留原截止时间和引用；默认继续仍使用原截止时间。
- 报告可以导出 Markdown。所有判断和时间节点均为待人工审核资料；本版不会自动合并到已审核事件时间线或自动生成脚本。

## 研究策略

内置通用背景、政策变化、公司事件三种策略。可新增、修改或停用；配置必查问题、优先来源域名、检索语言、检索次数、正文读取次数、时间预算。优先域名是研究指导，不是硬性来源白名单。新建课题保存策略快照，修改策略不会悄悄改变已有课题。

## 实现与边界

- `ResearchCase` 保存业务目标；`ResearchRun` 保存一次执行及 RunDesk 会话关联；问题、原文快照、判断和报告分别持久化。仅增加新表。
- MCP 端点 `/mcp/research` 使用 Streamable HTTP 的无会话 JSON 响应模式。提供 6 个工具：get_case、search、read_source、save_question、save_claim、save_report，实际名称均以 `research_` 开头。
- 工具调用按运行 ID 校验有效性。停止或被后续执行替代的任务不能写入。相同工具与参数的重试复用结果，不重复进行付费搜索；失败或结果未知的检索需要调整查询或检查后继续。
- MCP 证据检查验证来源归属、段落编号和摘录真实存在；它不能替代语义事实核查。研究 Skill 仍需判断证据是否支持结论，人也可以点击查看。
- 每次正文读取保存内容校验值和获取时刻；新内容形成新资料，不改写旧引用。未知发布时间明确显示未知。搜索服务日期过滤与网页元数据均不能保证严格的历史回放，报告需明确这类限制。
- 原始网页只读取公网标准端口，每次重定向重新校验地址并固定已解析的连接目标；上限 4 MiB、文本保留上限 100000 字符、PDF 最多 150 页。部分网站只能返回导航或验证页，Agent 必须记录资料限制。
- 研究服务使用现有单进程服务生命周期启动后台调度。HTTP 提交超时不自动重发；有远端会话时同步确认。进程中断后保留检查点，不声称恢复模型内部推理。
- 时间预算到期后拒绝新检索与读取，保留短暂报告整理时间，然后请求停止；远端不可达时标明状态待确认。网络读取也有独立超时。预算限制作用于本应用提供的研究工具。
- 研究任务在 `/research` 管理；原采集、脚本和视频任务中心保持原有行为。

## 验证

详见 [验证记录](validation-0.11.0.md)。自动化覆盖采用 RunDesk 0.5.4 接口契约夹具；官方 MCP 客户端及真实 Chromium 检查实际 HTTP 接口与页面。未连接用户的真实 RunDesk、Codex 或付费搜索账户，不能把模拟流程通过等同于真实研究质量通过。

验收建议：先选择一条熟悉的新闻，用较小预算完成一次研究；确认 RunDesk 轨迹中实际调用研究工具，报告证据能定位到原文，停止及继续正常。
