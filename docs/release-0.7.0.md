# 0.7.0：策略、试跑诊断与定时采集

本版在 0.6.0 的“采集 → 选新闻 → 生成脚本”流程上，补齐采集策略的日常管理。入口是导航中的“采集策略”，页面地址 `/profiles`。

## 策略怎么用

1. 新建策略，填写名称、国家、语言、关注分类和关键词。可以使用中文名称，也可以复制已有策略后修改。
2. 保存后点击“试跑已保存策略”，选择日期、时区，必要时勾选刷新新闻源缓存。
3. 在诊断页看新闻源取得多少条、来源与排除词留下多少条、相关性筛选留下多少条，以及样本被保留/过滤的原因。
4. 结果合适后，回“每日选题”正式采集；或在策略页下方新增定时计划。
5. 正式采集后选择新闻，生成脚本并继续编辑。定时计划只负责采集，不自动替你选题和发布视频。

“优先 AI”模式在模型不可用、调用失败、返回无效或遗漏部分判断时回退规则，并在诊断页说明。也可以明确选择“仅规则”。规则模式中，关键词与分类任一命中即可通过相关性筛选；若只想按关键词筛选，可清空分类。来源名单和排除词始终执行，先命中的限制作为该条新闻的过滤原因。

当前 WorldNewsAPI 接口按国家、语言和日期取热门新闻。关键词用于取得新闻之后的筛选，最大条数也在筛选前限制。**主动关键词检索尚未接入**，将在后续事件补充检索设计中处理。示例 `cn_policy_sectors` 表示中国政策与板块，并非 CNN 新闻源。

## 试跑与正式采集

| 项目 | 试跑 | 正式采集 |
|---|---|---|
| 请求新闻源、执行筛选 | 是，可能使用缓存并消耗上游额度 | 是 |
| 保存任务、运行记录、原始结果与诊断 | 是 | 是 |
| 写入新闻库、文章版本及事件关联 | 否 | 是 |
| 文章去重与新增/更新统计 | 不执行 | 执行 |
| 在每日选题里选择结果 | 需另发起正式采集 | 支持 |

诊断计数覆盖本次全部输入，明细展示输入中的前 50 条，每条只计一个实际生效原因；不是前 50 条保留结果。页面区分新闻源零条、来源/排除词全部拦截、相关性全部过滤、正式采集内容已存在四种情况。AI 相关性判断不能作为新闻事实核验。

试跑使用保存时的配置快照。编辑策略不会改变已经提交的任务；失败后重试会复用已保存步骤。希望比较修改后的配置或重新取得新闻，应发起新的试跑。旧历史任务没有逐条诊断时会明确提示，不推断原因。异常发生在筛选完成前时只能展示已保存的信息。

## 启停、删除与历史

- 停用策略时同步暂停所有关联定时计划，阻止新的采集和试跑。已经排队或执行中的任务按原配置继续，可在任务页取消。
- 重新启用策略后，关联计划保持暂停，按需要逐个启用。
- 删除策略前，须删除或改绑所有关联计划，并结束或取消未完成任务；直接命令行运行中的采集也算未完成任务。
- 删除策略保留新闻、脚本、任务、运行和试跑记录。历史失败/取消任务仍可按原快照显式重试，即使策略已停用或删除。
- 删除计划以归档方式保留其编号和历史引用，不取消已经提交的任务。归档的计划名称不再用于新计划，请另起名称。
- 编辑现有策略不会自动启用它。CLI、API、网页和调度器提交新采集时都会检查策略状态。

## 定时配置

支持每天、工作日（周一至周五）、指定星期和自定义五段 Cron。可预览下三次执行时间，时间含 UTC 偏移；计划列表显示下次时间、启用/暂停及上次状态。暂停计划的时间注明“启用后”，不会被当成已经安排执行。

时间使用 IANA 时区，如 `Asia/Shanghai`、`UTC`。自定义 Cron 支持数字、`*`、逗号、范围和步长。沿用旧调度器的语义：同时指定“日”和“星期”时两个条件都必须满足。夏令时中不存在的当地时间会跳过；当地时间重复时可能执行两次，对应不同 UTC 时刻。

服务必须持续运行。停止期间错过的执行时间不自动补跑，可从每日选题手动选择日期采集。调度器入队时重新核对计划的启停、策略、时区和时间条件，避免使用刚被修改或停用的配置。

## 从 0.6.0 升级

1. 停止服务，备份原数据库和整个 `storage_root`。
2. 解压本包，在原环境运行 `pip install -e .`，或安装 `release/news2douyin-0.7.0-py3-none-any.whl`。原视频可选依赖、FFmpeg 与中文字体配置继续使用。
3. 保留原 `.env`、数据库路径和 `storage_root`，按原参数启动。
4. 本版新增策略状态表；旧策略默认启用。已存在的新闻、选题、脚本、任务和计划继续保留，无需重建数据库。
5. 打开“采集策略”，检查原计划的时区和下一次执行时间，再试跑一个策略。

本版仍为 Python + HTML；未改动独立 RunDesk 程序。随包不附带真实 API Key。升级范围与并发验证以 SQLite 为准。

## 新增接口

| 接口 | 用途 |
|---|---|
| `POST /api/profiles/{name}/enable`、`/disable` | 策略启停 |
| `DELETE /api/profiles/{name}` | 检查关联关系后删除配置 |
| `POST /api/profiles/{name}/test` | 提交试跑；返回 202 与任务编号 |
| `GET /api/profiles/{name}/tests` | 最近 10 次试跑 |
| `GET /api/tasks/{task_id}/diagnostics` | 任务诊断与当时配置 |
| `POST /api/jobs/preview` | 预览 Cron 的下三次当地时间 |
| `PUT /api/jobs/{id}` | 编辑指定计划 |
| `DELETE /api/jobs/{id}` | 归档指定计划 |

原来的策略、计划新增和启停接口继续有效。无效参数返回 422，关联或状态冲突返回 409，不存在的对象返回 404。
