# 0.25.0 发布说明

本版把长期专题的主入口改为文字描述，系统据此生成可编辑的关注范围、关系模式和初始问题大纲，再通过后台任务回溯已有事件及持续处理新材料。

- 新建专题先填写一段“关注什么、希望弄清什么”的描述；实体、关系及手动范围放在展开区，保留原有手动建题方式。
- 使用已配置的模型解释描述，生成实体与别名、关注的行动关系、纳入排除原则及知识问题。模型不可用时明确显示规则解释方式，不将规则结果标为模型生成。
- 关注图表达用户意图，关系模式不代表事件已经发生；新闻中的陈述继续保留来源、固定版本和证据。
- 候选召回结合实体别名、已抽取的动作关系及扩展词项；专题级LLM进一步区分核心进展、背景材料、待核和不相关，保留判断理由与原文出处。
- 全局图的个性化关联排名可补充候选，但关联候选仍须通过专题模型判断；关注范围改变后，旧自动收录立即退出当前视图，人工选择与历史依据保留。
- 模型不可用、输出不合协议或无法定位证据时，保留待核材料。专题相关性与事实是否成立分别处理，否认或更正仍可能是重要进展。
- 保存专题不再在Web请求内遍历全部历史事件。后台按批次回溯，保留进度，支持重试；专题页面展示处理状态。
- 人工关联及排除优先于自动处理；定义或材料版本改变后，旧任务不能覆盖新设置。

本版使用实体、动作和词项召回，未增加独立向量数据库，也不声称已提供全量新闻的密集向量语义检索。全量GKG原档留存方式不变，归入专题与原始采集是独立过程。查看[专题使用与运行说明](TOPIC-TRACKING.md)。

实际验证与边界见[0.25验证记录](validation/0.25.0/README.md)。

升级前停止旧服务并备份原数据及配置。继续沿用PostgreSQL或SQLite事务连接、完整存储目录和FalkorDB命名空间；本版为新专题状态增加独立业务表，不要求重建旧专题或清空图。SQLite切换到PostgreSQL继续使用已提供的停源迁移工具，参见[数据库迁移说明](POSTGRES-OPERATIONS.md)。没有迁移或修改用户现场的27GB数据库。
