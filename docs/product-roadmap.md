# news2douyin 产品关系与分版本计划

## 产品主线

系统按策略自动采集新闻。用户每天看列表，挑选通常 1–3 条，然后准备脚本、制作视频。完成的视频需要留存、可查看并可导出。后台任务、日志和配置为这条流程服务。

## 模块关系

| 模块 | 保存什么、解决什么问题 | 与其他模块的关系 |
|---|---|---|
| 新闻库 | 一篇篇报道：原文、来源、发布时间、采集记录、内容版本 | 所有分析和脚本的资料基础 |
| 每日选题 | 今天打算制作哪些新闻及其脚本状态 | 从新闻库中选择；并非复制一套新闻数据 |
| 事件专题 | 对同一件事的多篇报道及其来源 | 从新闻库关联报道，支持人工增删、合并拆分；自动规则关联仍需核对 |
| 事件发展脉络 | 事件中每个进展的发生时间、说明、证据与不确定性 | 置于事件专题内部，人工整理进展并固定来源版本，可关联背景/后续专题、补充检索、导出证据包；为深度脚本提供结构化背景 |
| 脚本工作台 | 标题、口播、画面提示、所用来源、版本和审核状态 | 以所选新闻或确认过的事件资料生成；输出制作包 |
| 视频与成片 | 配音、素材、字幕、渲染任务和最终 MP4 | 使用已确认的脚本版本；保留预览与导出入口 |
| 新闻长图排版 | 根据已有内容排版的 HTML/长图辅助素材 | 当前旧“时间线”工具；并未进行事件调查或时间核验 |
| 采集策略与运行管理 | 收集内容的范围、定时计划、进度和失败诊断 | 控制新闻何时进入新闻库，不代替人工选题 |

需要区分四种时间：报道发布时间、系统采集时间、事件实际发生时间、视频中的播放时间。前两种可以直接搜索；事件实际发生时间需要来源支持；视频播放时间属于制作分镜。这四者不应共用一个含糊的“时间线”入口。

## 版本安排

| 版本 | 重点 | 验收标准 | 状态 |
|---|---|---|---|
| 0.6.0 | 每日采集 → 选择 → 脚本；时间筛选；基础策略新增/编辑/复制；模块命名与引导 | 不看 API 文档也能在网页完成一次选题与初稿；刷新保留选择；重复生成返回已有稿；模型错误可重试 | 已交付 |
| 0.7.0 | 策略与自动采集管理 | 策略增改、复制、停用/删除；被定时任务使用时明确处理；可试跑并显示抓取数、过滤数和零结果原因；日程与时区同页配置；区分热门榜采集与主动关键词搜索 | 已交付 |
| 0.8.0 | 事件专题与发展脉络 | 用户选一个事件，可加入/移除库内报道；合并/拆分保留来源；时间节点区分发生时间和发布时间；相关事件与外部检索可追溯；不确定时间明确标记；策略支持主动关键词检索 | 本次交付 |
| 0.9.0 | 有证据的脚本工作台 | 可选快讯/解释/事件复盘、时长与风格；以确认过的脉络生成脚本；逐段来源、事实与观点区分；分镜与素材需求可编辑；生成接入后台任务，页面关闭后可续办 | 待实现 |
| 0.10.0 | 视频制作与作品库 | 脚本版本 → 配音 → 字幕 → 画面 → 成片；具备可用默认模板、环境诊断和失败恢复；作品按标题、封面、日期展示，支持 MP4/字幕/制作包导出 | 待增强 |

0.6.0 的 AI 中文稿只使用所选报道，不能替代 0.8.0 的调查补充和 0.9.0 的有证据的深度复盘。0.10.0 会增强已存在的基础视频渲染，而非把当前能运行的功能视为未实现。

## 推荐推进顺序

先实际跑通一天：采集、选两条、生成并编辑脚本，验证日常操作是否顺手。0.7.0 已补齐策略管理、试跑诊断和定时配置。0.8.0 已实现人工整理脉络、来源版本绑定与主动关键词检索。接下来推进 0.9.0，让生成脚本真正使用已整理的脉络和逐段证据，再集中提升视频质量与作品管理。

真实新闻源和本地模型的可用性、限额与输出质量需在用户部署环境验证。本次离线样例和模型响应桩验证的是软件流程，不能证明真实新闻检索覆盖率、稿件事实准确性或视频传播效果。
