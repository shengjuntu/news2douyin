# 0.25.1 发布说明

本版针对大量历史事件积压时图投影缓慢的问题优化热路径，并将必需图索引纳入启动后的后台检查。继续保留0.25.0的文字建题、专题筛选与数据库迁移工具。

## 主要变化

- 事件投影继续按stamp定向删除旧关系，移除每条事件后执行的五条全图孤儿清理。维护工作单独记录进度，失败不会让已完成事件因清理错误而反复投影。
- 启动后检查全局图及实际使用的专题图所需ID/地域属性索引；只补建缺失项，等待服务器报告索引可用，不删除正常索引或清空图。检查和建索引在后台执行，不在Web请求中执行。
- 跳过空集合的写查询，合并事件与来源的基础更新；保留空来源事件、更正、删除及共享来源的语义。
- 待办队列使用有条件索引和事件/专题公平调度，当前版本真正完成的任务才计入成功确认。缩短忙碌时的固定等待，保留空闲等待及错误退避。
- 现有知识状态页分别显示索引准备、图投影、图分析时间和维护状态；详细统计折叠显示，不增加菜单。

仍保持单图写入者和原全局租约，未启用同一图的分片并行写入。图节点投影与图排名/聚类刷新是不同阶段，不能把节点数增加等同于分析结果已更新。

## 升级

停止旧服务，备份数据库、完整存储目录、配置与FalkorDB数据后安装新包。继续沿用原数据库连接、storage_root、图地址与命名空间。新维护状态使用独立业务表；不要求清空图、丢弃原始GKG或删除历史文章版本。

启动后的首次索引准备时间随现有图规模变化，状态页会显示进度；Web页面仍可读取已有材料。若图服务权限、资源或建索引失败，可在状态页重试维护检查。重试不等于重建全部图数据。

SQLite切换到PostgreSQL仍使用原有停源迁移流程，详见[数据库运维说明](POSTGRES-OPERATIONS.md)。本次没有访问、修改或迁移用户现场的27GB数据库。

性能结果及限制见[0.25.1验证记录](validation/0.25.1/README.md)。本地合成图性能不能代替现场持续负载验收，也不用于承诺44万条积压的追平天数。
