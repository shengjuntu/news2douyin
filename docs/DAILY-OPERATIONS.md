# 每日精选与历史补采

## 阅读今天的进展

打开事件雷达的「每日精选」(`/radar`)。日期使用北京时间。上午收到的材料已经可以入选，有几条符合条件就显示几条，每期最多 100 条。初次生成点「生成今日精选」；当日下午可点「重新生成今日精选」，继续使用同一日期和地址。

默认后台也会更新当日版，成功生成后约 15 分钟到期再排队。页面上的「资料截至」给出此次选取的观测边界。后台运行或本次更新失败时仍可读上一版。成功后整期一次替换；已经送到工作台的选题保留当时的标题、摘录和来源。跨日后后台会收尾当天的滚动版。

## 分组、排序与阅读位置

先选「分组」，再选「排序」并点「查看」。可以保留推荐顺序，也可以在每组内先读最近观测的进展。跨日或浏览历史补采时，「最近观测」采用本系统的观测时间。

| 分组 | 依据 |
| --- | --- |
| 国家或地区 | 官方事件使用行动发生国，GKG 使用报道涉及的国家。提及多个国家时只展示一张卡，保留其他国家标签。证据不足时归入多国或未识别组。 |
| 分类 | 使用已保存的事件类别或可追溯的 GKG 主题。旧数据缺少依据时保留未分类。 |
| 数据来源 | 区分 GDELT Events、GDELT GKG、已整理事件和 NewsNow。卡片保留相应来源链接。 |

序号按当前阅读顺序从 1 连续排到最后一条。点击序号标记位置，再点「回到上次读到的第 … 条」。浏览器按日期和进展标识记忆；换排序或换版，只要该条仍在榜上就能定位。标记保存在当前浏览器。

在单卡点击「译成中文」可译当前标题和已有摘录。翻译沿用系统的模型设置、后台队列与缓存。等待翻译时可以继续读。已有译文和原文分开展示。未配置模型时可从卡片进入设置。同一条更新了原文需按新版材料译读。

在页首用 Markdown 按钮下载当期全部入选材料，再交给 Codex 挑选视频题材。[完整清单与编辑流程](DAILY-BRIEF.md)

## 补一期日报，还是补采数据

从每日精选右上方或运行管理打开「日报管理」(`/admin/daily-radar`)，选中北京日期。可查看当期版本、按流的已归档数、已到但缺少的批次、未来时段和后台进度。

| 遇到的情况 | 操作 | 结果 |
| --- | --- | --- |
| 当日尚未出刊，或历史资料已经在本地 | 用已有数据生成／按已有数据重算 | 后台重算当期；无需重复下载原始数据。 |
| 历史日期的 GDELT 记录有缺口 | 补缺并重算 | 逐批核对当天启用的归档流，补取缺口。全部核对成功后才自动重算并确认发布。 |
| 上游缺档或请求持续失败 | 查看错误，重试补采 | 已归档的批次再核对，继续补取剩余缺口。 |
| 部分批次始终补不到 | 用已补齐的批次重算 | 显式发布部分结果；管理页保留未补齐的批次。 |

完整北京日每条启用流有 96 个 15 分钟时段，六条全部启用时有 576 个待核时段。今天只将已到点的时段计入预期。这里的缺口指本地接收账本里的缺口。后台任务核对 DuckDB 归档清单，遇到缺少的批次时复用本地有效 ZIP 或向上游补取。任务和进度落在工作库，数据写入由采集接收器负责。

历史重算可以纳入补回的 GKG 标题，保留原始批次及本机实际收到的时间。补回的 Events、Mentions 原始记录仍可用于材料检索和后续处理。仅靠补采无法重现编辑在历史当天实际看过的全部报道、原文、榜单或当时的排序。NewsNow、NewsAPI 和本地采集只使用已保存的资料。
