# 0.26.0 存储职责、冗余与升级

本版保留 PostgreSQL＋DuckDB＋FalkorDB。原始档案、操作状态与图投影分别承担不同职责，采用稳定身份和可核对的引用关联。所有归档记录先保留；选题筛选不改变接收完整性。新增官方 Events/Mentions 是来源事件及报道关联输入，不自动等同于已经核查、跨报道融合完成的本地研究事件。

## 权威资料和可重建结果

| 内容 | 持久来源与用途 |
| --- | --- |
| 原始GDELT ZIP | 保存下载字节及归档校验链，作为原始证据；保留feed、批次、归档SHA和行号 |
| DuckDB记录 | 提供原始记录的可检索归档及解析入口；处理版本和派生字段可以重算，原始载荷必须可复核 |
| PostgreSQL | 管理身份、文章版本、人工判断、选题与研究状态、投影回执；本地业务关系和不可变证据引用是恢复基础 |
| FalkorDB | 为遍历、相关性与分析物化结构，保存必要属性；数据可重放，但恢复时间、图算法版本和服务可用性仍需要考虑 |
| 派生排名与关联 | 由代码中的分析算法计算，分别写入图与PG读取缓存；使用同一代次比较，不能只按属性存在数量判断谁是最新结果 |

`articleeventlink`与`HAS_SOURCE`分属事务关联和图遍历路径，两者不能简单二选一。`textmention`及不可变文档版本提供证据依据，图中的EventMention/Argument/Referent用于遍历；必要投影副本具有明确用途。`graphmetric`与`graphrelation`还保存代次、依据和读取缓存，不因图中存在相似属性而自动删除。

## 本版优化范围

新增归档行采用单份原始载荷和紧凑检索字段，避免同时持久保存大份原始行与完整解析JSON。详情与有界处理批次按需解析；非法UTF-8的原始字节仍须保留。GKG的大GCAM、增强字段和XML保留于归档；新的PG工作索引只复制筛选和业务运行需要的紧凑字段及可追溯指针。外部应用接入的正文、人工选择及既有不可变历史版本继续保留。

旧DuckDB表仍可读取，不在正常启动或Web请求中重写几十GB数据库。离线压缩/迁移工具写入新的目标文件，核对原档校验值、批次、行号、载荷及可重建解析结果后再报告。旧文件不会被自动删除或替换。实际文件大小、运行时间与可用空间应由工具在具体数据上实测；没有对现场58.75GiB文件完成迁移或承诺节省指定GiB。

本次不自动删除原始ZIP、SQLite历史文件、PG业务关联或图快照，也不关闭FalkorDB持久化。旧SQLite可以在完整核对迁移、备份和恢复路径后，由操作员另行归档；`lsof`无占用只能说明检查瞬间未发现打开句柄，不能单独证明历史内容已完整迁移。

## 对现场冗余报告的口径修正

现场报告提供了有价值的容量和字段样本，但下面的结论需要与计量方法分开：

1. **字符数不等于字节数。** 报告中的`SUM(length(raw_line))`、`SUM(length(metadata_json))`和Python `len(str)`测量字符数。捆绑DuckDB实际检查`length('中')=1`，`strlen('中')=3`。UTF-8逻辑字节可用`strlen(VARCHAR)`或`octet_length(encode(VARCHAR))`；二者仍不代表数据库物理压缩占用。
2. **逻辑载荷之和不能直接换算可回收文件大小。** DuckDB文件还受列编码、压缩、索引、块复用和空闲页影响。样本zlib比例也不能直接乘当前文件大小；应对新文件完成写入、关闭及核验后报告物理字节。普通删除或更改列不应被承诺立即缩小文件。
3. **GKG JSON不包含完整原始27列的全部信息。** 以本版继承的解析器为例，原始第6/7列是Counts/V2Counts，第17列是增强日期，不是作者或空列；Counts字段并未逐字完整保存在解析metadata中。人名等列表有拆分和去重、XML有解码，因此解析JSON是派生表示，不能用它无损反推原始字节。原ZIP与单份原始载荷是保留证据的基础。
4. **PG与图数量相差约21%不能单独证明某条过滤规则。** 还需核对同一时刻的`GraphPending.token/written`、RadarEntry是否存在、合并/删除状态、范围及命名空间等。当前GKG投影已在生成PG文章前校验报道URL，所以“PG中已有文章但图中没有”的差额不能仅用非HTTP过滤解释。可将差额当作待核对问题，不能直接视作全部已处理。
5. **图属性存在不等于当前算法代次。** 当前分析只取有限事件窗口，较旧Event节点的score属性可能仍保留。比较PG GraphMetric与图Event应先对齐`generation/analysis_generation`及分析水位，不能用所有带score属性节点的数量作为本轮分母。
6. **可重建不等于无需持久化或备份。** 大图重放需要源数据、同版本代码/模型、稳定命名空间及足够时间。FalkorDB持久化用于缩短恢复时间；PG人工状态、不可变证据和原档仍需独立备份与恢复演练。

源码实际的来源边为`Event → HAS_SOURCE → Article`，证据提及为`Article → DESCRIBES → EventMention`。报告中的方向文字不应替代实际图契约。

## 生产数据库配置保护

正式Compose启用：

```dotenv
NEWS2DOUYIN_DATABASE_REQUIRE_POSTGRES=1
```

该开关在解析默认运行数据库连接时生效。若`NEWS2DOUYIN_DATABASE_URL`缺失、无效或不是PostgreSQL，服务在打开任何旧SQLite文件前明确失败，错误不包含连接凭据。正式Compose仍构造内部PG连接，并保留原图地址和命名空间。

本地开发默认保持`NEWS2DOUYIN_DATABASE_REQUIRE_POSTGRES=0`。离线迁移、测试或开发明确传入SQLite地址的调用继续可用；该保护用于防止生产默认配置静默回落，不阻断有明确地址的维护工具。历史SQLite文件不会因此被改名、删除或自动压缩。

## 采集与工作索引控制

```dotenv
NEWS2DOUYIN_GDELT_STREAM_ENABLED=
NEWS2DOUYIN_GDELT_PROJECTION_ENABLED=
```

两个新名称是通用主开关：留空或未设置时分别沿用`NEWS2DOUYIN_GKG_STREAM_ENABLED`与`NEWS2DOUYIN_GKG_PROJECTION_ENABLED`。显式0/1覆盖旧名称。这样，既有现场暂停设置不会因升级被悄悄启用；确需覆盖时可明确设置通用主开关。

各英文/翻译的GKG、Events、Mentions流仍在采集页分别启停。原档接收与PG工作索引推进可独立暂停。任何选题过滤都在归档之后执行，不据此跳过或删除上游记录。

## 现场验收顺序

先核对原服务的数据库连接、存储目录、图命名空间和备份；启动后确认各流批次及失败重试可见。验证官方事件与提及的来源标识、初始提及计数和实际观察到的文档数分别显示，过滤不会改变归档数量。用少量选中题材走通选题、来源关联与研究入口。

旧库瘦身独立安排维护窗口：确认没有接收器或DuckDB读写者，写新目标并核验，记录源/目标文件字节及用时，保留源文件后切换。大库迁移不是安装新版后自动发生的操作。
