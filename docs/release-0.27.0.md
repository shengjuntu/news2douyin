# 0.27.0：发现、译读与研究工作台

本版整理已有页面和操作顺序，继续保留事件雷达、我的专题、内容工作台、新闻库四个主入口。运行管理用于采集、索引和执行诊断，不再向日常选题增加主菜单。

## 雷达与来源详情

全球线索列表突出主体、行为、对象、发生日期、地点及本站已观察的媒体域名/报道数。已形成选题的线索优先继续原任务，另起角度为次要操作。事件编号、编码和说明放在详情侧栏；关闭侧栏保留筛选和分页位置，工作台可以直接回到对应线索。

侧栏集中展示原始报道链接、归档依据、发生日期和观察时间、官方有向行为关系、地点以及中文译读。关系图支持缩放和点击主体筛选，地图只高亮官方行动地点所属国家/地区；缺失角色或坐标不补造。图描述官方自动编码的行为线索，仍需原文核查，不是经过研究确认的因果图。

基本筛选保留关键词、国家、行为、时间；高级条件折叠。保存筛选后立即可切换。专题条件明确标为关键词召回，与专题已接受材料分开。已删除专题的旧书签/保存方案显示恢复或明确移除条件的入口，不静默扩大筛选范围。

雷达概览区分归档与索引，可展开六条流逐项查看；索引进度不跨过已知待处理缺口。最新完成批次不是全部历史完整性的承诺。

## 语言与按需中文译读

新闻库和固定版本详情显示已保存语言字段及中文名称。字段缺失时显示未知；文字形态只能作为明确标注的推测，拉丁字母不会自动判为英语。Events/Mentions没有可直接作为原报道语种的字段，官方线索明确显示未知。

点击后才使用已有兼容模型配置，在现有执行队列中翻译。可译标题、所查看版本已存正文、固定资料快照或官方线索字段，保留原文和版本。翻译失败可重试，结果仅作阅读辅助，不改写文章、事件、快照或引用证据。没有正文时不会声称翻译了新闻全文。

译读复用`OPENAI_BASE_URL`、`OPENAI_API_KEY`、`MODEL`；配置入口在首次运行检查的“译读与脚本模型”。它与RunDesk补材/深研究配置分别生效。HTTP提交不等待模型；译读可能排在已有采集/制作任务之后。标题最多1000字符、正文和事件线索最多6000字符，超出时注明只译前一部分。详见[译读说明](READING-TRANSLATIONS.md)。本轮离线测试验证了任务、版本和交互，未评价用户实际模型的译文质量。

## 工作台的下一步

修正官方线索错误链接：这类资料没有对应Article，入口改为冻结快照、来源依据和雷达详情。工作台明确区分“只有线索”“已有可读材料”“已有研究报告”，提供相应的补材、研究或创作入口。

## 专题删除与恢复

专题标题旁增加删除入口，确认后移入回收站并停止跟踪。保留报道、事件、独立内容任务和研究成果。待提交自动补查取消，在途匹配结果不能发布到已删除专题；已提交研究作为独立任务保留。恢复后保持暂停，原有已接受材料仍可查看。专题图异步标记归档，不删除共享证据关系。此操作不用于回收磁盘空间。详见[专题回收站](focus-recycle-bin.md)。

## 总量、页数和性能

全球线索默认显示当前页，点击“查看总条数与页数”才执行当前筛选的窄列COUNT。统计有2.5秒SQL时限、单实例30秒短缓存，注明统计时间；超时保留翻页和重试，不猜测总量。总数只包括本站当时已索引的匹配记录，持续接收会改变页数。

本地已整理事件复用原来的异步统计显示页数，新闻库和通用分页同时显示总页数；不增加首页全表正文加载。延续全球线索原有深分页上限，超过后需缩小范围。
