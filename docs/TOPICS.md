# 选题工作台 · 0.16.0

统一入口为 `/topics`，首页 `/` 也进入这里。顶部“选题工作台”取代单日选题入口，旧采集/日选流程保留在 `/daily`，可从工作台右上方打开。

## 操作

- 对话选题：输入一句话，点击“新建选题 / 开始讨论”。无需先选新闻。助手查历史报道和事件、读原文、保存候选和回复。采用候选后可继续追问、调整角度和资料。
- 手动选题：输入框留空后新建。按关键词、全部历史/今天/近7天/近30天/自定义日期检索，支持发布时间、首次入库时间和报道采集时间。事件按关联报道的日期筛选；事件按采集时间检索暂不支持，可切换为报道检索。打开事件的关联报道后可逐条加入。
- 保存选题：标题、角度、检索范围、已选原文快照独立于日期保存；下拉框可切换选题。候选需显式采用，助手不会直接覆盖用户选择。相对日期保存时转为明确日期，跨天继续时范围不漂移。
- 继续讨论：同一选题复用同一 RunDesk 会话，每条消息固定当时的选题范围与资料。背景修改不会覆盖旧消息。一次仅执行一轮讨论，停止或结束后可追问。
- 查看依据：候选和回复的“来源”打开保存的原文快照；已选报道更新后不改写旧快照。再次主动加入同一报道会选择新的当前快照。

## 选题之后

| 操作 | 行为与结果 |
| --- | --- |
| 仅用所选资料写短稿 | 不分配外部检索或新增正文预算；读取已有证据快照，保存带引用短稿 |
| 补充材料，勾选“补材后生成短稿” | 原有轻量补材链路：最多3次外部搜索、6次新增正文读取、5分钟工具预算，可保存候选配图并生成短稿 |
| 补充材料，取消上述勾选 | 同样轻量预算，保存素材报告、依据与缺口；配图为来源页面线索，未自动下载或核实授权 |
| 深入研究 | 使用当前背景研究策略，保存完整或部分研究报告、证据与问题 |

短稿最多合并6条相关资料；一个选题最多选择12条。输出语言支持简体中文、英语和日语。短稿目标时长为30/60/90/120/180秒，不代表真实配音长度。补材/研究默认截至发起时刻，初始检索日期写入任务要求；查询历史资料并不自动把研究截止时间设为过去。

研究是独立子任务，原文与参数在交接时固定；列表保留关联入口。修改选题后旧任务仍保留，发起新任务不会覆盖旧结果。仅生成素材报告时不能把配图线索当作已下载、已授权的图片。

## 执行和恢复

news2douyin 保存选题、快照、讨论和交付关系，RunDesk 承担 Codex 会话和执行。选题轮次复用现有执行器的排队、环境准备、提交回执、停止与重启恢复。其内部执行记录通过专门的选题绑定与普通研究分开，默认研究课题列表不展示选题讨论记录。

`topic_*` 工具只访问本地数据库，不发起外部搜索或抓取 URL。完整访问容器里的其他工具仍取决于现有 RunDesk 配置；这不是容器级网络隔离。选题提示要求仅调用库内工具。外部补材继续使用 `research_search` 发票据、Codex/Exa 搜索、结果回存与原文读取的单一路径。

保存库内查询的范围、时间、匹配数量和结果快照；同一轮相同工具参数复用结果。每轮最多30次库内查询、30份原文读取，候选最多5个/次；单选题最多100轮讨论、300份资料、75个候选。当前使用关键词/全文索引与字面匹配，没有向量语义检索；摘要和候选均需要人工核对。对话回复不等同于经过研究审核的最终报告。

创建、消息和交接均使用持久请求编号；同号同内容复用，换内容拒绝。浏览器将未确认请求保存在本标签页 sessionStorage；刷新可以核对原请求。关闭标签页会丢失尚未到达服务端的客户端记录，服务端已接收的任务仍保留。交接记录已保存但环境未配置时，返回待继续的原任务，配置后点击“继续提交原任务”。

## 升级

1. 等待或停止当前任务，停止 news2douyin，备份完整数据库、运行目录和配置。
2. 在原 Python 环境，从本包根目录执行：

```bash
python -m pip install -U './release-0.16.0/news2douyin-0.16.0-py3-none-any.whl[research]'
```

源码方式可用 `python -m pip install -U '.[research]'`。使用原数据库和 storage 路径重启，不要换成空目录。

3. 启动时新增6张 Topic* 表，旧日选、研究和脚本表不增加字段。页面应显示0.16.0，默认进入选题工作台。
4. 在研究助手设置执行连接检查。MCP 地址和 Token 不变，总工具数由8变为13，增加5个 `topic_*`。如 RunDesk 缓存旧工具，刷新 MCP 发现或重新连接配置后建立选题会话。无须因本版修改 RunDesk 代码或重建 Codex 研究镜像。
5. 手动历史检索不依赖模型；对话需要现有 RunDesk 模型认证与 MCP 回调。原生本地模式的选题检查不要求 Exa；Docker 仍需通过已有绑定环境的准备/认证探测。外部补材/研究仍需要 Exa。
6. 用历史报道验证：搜索 → 加入 → 查看原文 → 保存 → 刷新恢复。再输入一句话讨论 → 采用候选 → 追问 → 补材或研究 → 返回查看关联任务。调试时打开 RunDesk，按页面显示的会话编号查看轨迹。

已有 `/daily` 选择不自动转换成新选题；原脚本、研究和任务仍从旧入口查看。回退版本前恢复升级前完整备份。

## API

| 接口 | 作用 |
| --- | --- |
| GET/POST `/api/topics` | 最近100个选题 / 幂等创建，request_id、title?、scope? |
| GET/PUT `/api/topics/{id}` | 选题、消息、候选和任务 / 按 revision 保存 title、angle、scope、source_ids |
| GET `/api/topics/{id}/search` | kind=articles/events、scope(JSON)、offset、limit；不会自动选择或启动研究 |
| POST `/api/topics/{id}/sources` | revision、article_key，固定当前原文并加入 |
| GET `/api/topics/{id}/sources/{sid}` | 此选题的原文快照 |
| POST `/api/topics/{id}/messages` | revision、request_id、text；返回持久 run_id |
| POST `/api/topics/{id}/sync`、`stop` | 核对原执行 / 停止本轮 |
| POST `/api/topics/{id}/handoffs` | revision、request_id、action(short/materials/deep)、output_language、duration_sec、find_images、write_script |
| POST `/api/topics/{id}/handoffs/{hid}/resume` | 按保存的参数继续交接，不创建替代任务 |

scope 支持 query、period(all/today/last7/last30/custom)、date_from/date_to、time_field(published/created/collected)、timezone、event_key。默认全部历史，时区 Asia/Shanghai。

选题 MCP：`topic_get_workspace`、`topic_search_library`、`topic_read_article`、`topic_save_candidates`、`topic_save_reply`，均需本轮 `turn_id`。来源必须在当前选题实际读过；结束或停止后写入会被拒绝。旧8个研究工具继续使用 `run_id`，不能用于选题讨论轮次。

验证范围见 [0.16.0 验证记录](validation/0.16.0/README.md)。
