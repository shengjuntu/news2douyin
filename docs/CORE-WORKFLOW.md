# 0.20.0：知识底座与连续内容工作台

## 日常操作

主导航为事件雷达、我的专题、内容工作台、新闻库。采集、研究连接、知识处理状态与执行记录集中在运行管理。

1. 在采集配置保存策略，试跑检查结果后点击“正式采集入库”，或设置定时计划。采集入库后，事件抽取、图同步、图分析和专题归集由后台持续执行。
2. 事件雷达按图分析结果排序；点击事件查看报道、原句、来源树、地图和时间线。排序显示行动影响、不同陈述、来源去重组与图关联度。
3. 从雷达点击“形成选题”，或在专题内点击“从专题形成选题”。明确本次问题和日期范围；默认带入范围内最近 6 份报道，选题阶段可以调整，最多 12 份。
4. 同一内容任务内依次查看选题、研究、创作、作品。选题讨论仍由 RunDesk/Codex 执行；可用已有资料写稿、轻量补材或深入研究。请求及原文在交接时固定，重复提交复用原请求。
5. 研究结束后，选择明确版本的报告，点击“基于研究创建可编辑初稿”。系统将有支持证据的判断带入稿件，保留逐段引用、报告 ID、版本和内容校验值。此步骤形成研究判断提纲，尚未执行另一轮模型改写；请在编辑器调整叙述。没有支持证据的判断不会变成事实段。
6. 保存、审核、导出稿件或制作视频。报告、制作包和视频出现在同一任务的作品阶段。报告本身可以交付；不要求每个任务都制作视频。作品仍能回到任务、研究、专题及固定版本的原文。

一次任务完成后，所属专题继续跟踪。新材料和研究不会自动改写已导出的作品或旧报告。

## 两层图的职责

SQLite 保留原始报道版本、抽取陈述、人工选择、任务与产物记录。FalkorDB 是完整雷达与专题图分析所必需的服务；事务型 GraphPending 队列负责可重放写入。SQLite 中的 GraphMetric/GraphRelation 是从 FalkorDB 读出并计算后发布的缓存，不是替代图数据库的查询引擎。

- `n2d_active_global`：报道、事件陈述、论元、实体候选、事件、地点与专题根节点；保留原文位置、版本、角色、事件状态和时间精度。
- `n2d_focus_<专题编号>`：专题根问题、长期知识点、相关事件、调查、研究问题、结论、证据及报告版本。实体与事件使用全局稳定标识；跨图关联由应用按标识完成。
- 结构契约：`src/news2douyin/extraction/graph-schema.yaml`；运行时 `/api/desk/graph-schema`。

模型抽取读取带编号的原文段落，输出结构化事件及论元。程序验证摘录和偏移，拒绝无法定位的关系。规则作为有限的离线基线；开启模型抽取并重启后，已有当前版本的规则结果会自动进入模型补全队列。抽取方法、处理状态与人工核对状态均可查看。暂时性网络错误最多自动重试四次；结构或证据校验错误直接标为失败，保留已有抽取。

同名归一化产生 `name_candidate`；只有内置明确别名标为 `curated`。未解决一般性同名消歧。计划、否认、条件与已报道行动分别保存；发布时间不冒充发生时间。GKG 地点提及、媒体来源国和有证据的行动地分别展示。

## 实际使用的图算法

1. 具有相同动作、状态、明确日期、参与角色和地点的陈述建立严格匹配候选。它帮助关联报道，不自动硬合并事件记录。
2. 从图中读取有原句依据的参与者边，在 30 天窗口内构造事件关联；单个名称连接超过 60 个事件时不用于扩散，避免热门名字支配全图。每条关联保留构造依据。
3. 在有权事件图上执行 PageRank 和确定性的有权标签传播，计算关联度与相关群组。算法运行在应用分析进程，输入来自 FalkorDB 的只读查询，结果写回图并发布缓存。群组不代表同一事件，也不表示因果关系。
4. 雷达分数由动作类型、不同陈述、已识别的来源去重组和图关联度组成。分数达到 60 标为“优先看”，35–60 标为“优先核查”，其余为“其他进展”；筛选与排序采用同一结果。权重为初始可解释规则，尚未经真实新闻重要度标注校准；来源去重组不等于独立证实。
5. 专题以直接范围匹配和人工关联作为种子，执行个性化 PageRank，再按排名对一跳有证据的关联最多扩展 30 个候选。排除词和限定议题保持生效；人物专题不因他人关联自动扩展。人工包含/排除优先。
6. 知识点按词项与材料重合形成相关材料线索，明确标为“相关性待核”，不会写成结论的支持证据。LLM 研究产生的问题会进入持久大纲。自动复查优先覆盖材料不足、较久未查的知识点，每专题每日最多触发一轮自动研究，并沿用研究策略预算。

当前全局分析限定最近 5000 个事件，图视图最多显示 60 个节点；超出范围时明确提示。全历史原文和专题材料仍保留。当前使用稳定全量窗口重算，尚未实现大规模动态图增量算法、开放域实体消歧、可靠自动因果发现或已校准的重要度概率。

## 故障和恢复

`/knowledge` 展示抽取队列、索引、图同步、最近分析时间及重试入口。FalkorDB 不可用时采集、原文与已保存成果可访问，雷达/专题显示未就绪或过期状态，后台重试。图恢复或丢失后按队列重建；原始材料不会丢失。

每套 SQLite 数据库配置独立 `NEWS2DOUYIN_GRAPH_PREFIX`。系统保存图所属数据库标识，发现同一前缀属于另一数据库时停止写入。部署采用单个应用服务进程（一个后台图写入者）；当前不支持多个应用进程同时更新同一图。

## 旧页面与升级

升级新增表，不删除新闻、研究、脚本和视频数据。原选题草稿转换为内容任务，已保存交接绑定研究；生成的短稿绑定回同一任务。独立历史研究和稿件在工作台“历史成果”中，可点击“继续这项工作”纳入新任务。

`/topics` 转到内容工作台；`/daily` 转到新闻库；独立脚本和补材列表转到相应工作阶段；已有详情链接在存在归属时转到任务内部。删除不再使用的每日选题、独立脚本列表、旧事件列表/详情和研究列表模板。采集入库移至采集配置；旧 API 保留，供已有客户端和历史任务使用。

备份并沿用原数据库、运行目录和配置。安装 `release-0.20.0` 中的 wheel；必须配置 FalkorDB 后再把图状态当作就绪。模型抽取和 RunDesk 研究需分别连接自己的运行环境。回退时恢复升级前备份。
