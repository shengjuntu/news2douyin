# 0.5.0：文章版本、事件关联和全文检索

本版回到原优化计划的新闻数据部分：相同 URL 的更新保留为新版本，转载识别与事件关联分开，文章和事件查询增加全文索引、总数与分页。继续使用 Python + HTML，Go Video App 保持 0.5.0。

## 文章身份与版本

- 按规范化 URL 固定文章身份；移除跟踪参数后同 URL 的标题、正文、来源、发布时间等变化形成新版本。无 URL 时使用 provider、标题、发布时间、国家组成身份，无法识别无 URL 且改标题的同一文章。
- 完全相同的内容再抓取不会产生版本；A → B → A 会保留三个观察版本。编号按本系统观察顺序，不声称还原源站真实编辑时间。同一 URL 被网站改作另一篇文章时仍按版本处理，不自动改变事件归属。
- 版本保存原文、元数据、原始输入、SHA-256、观察时间与采集运行标识。新闻库可查看各版本及与上一版的正文差异。
- 新生成的脚本来源增加 `article_revision` / `article_content_hash`。已有脚本/审核/导出快照保持不变，包 schema 仍为 1。
- 采集任务记录采用的文章版本。重试导出使用当时的版本，即使另一采集任务已经更新了当前文章，也不会替换旧任务的导出内容。
- 新增、版本、事件关联、统计及任务条目在一个数据库事务内提交。采集写入通过短事务串行化，网络抓取/LLM 过滤在锁外完成。

## 转载与事件归并

转载依据足够长的正文相同或高度相似；同标题和旧的 LLM“同事件”判断不再直接把报道标成副本。完全相同正文的哈希查询覆盖全库，近似副本比较仍最多检查最近 1000 篇同国家文章。

独立报道的事件关联采用保守规则：同国家、同语言、发布时间相差不超过 3 天，再比较标题词项、正文词项和文字相似度。候选最多 250 篇；标题数字、否定表达和开头主体冲突时不自动关联。缺少有效发布时间时不执行独立报道规则归并。转载跟随已保存的原文事件，不受这个时间窗口限制。

新事件使用一次生成并持久化的 ID；旧事件和文章 ID 保留。规则记录匹配文章、原因及分数，分数是词项相似度而非概率。事件详情区分文章数、独立报道数、来源域名数、转载/副本数；不同域名不等于完全独立证据。

这是规则归并增强，**不是已完成的大模型语义聚类**。跨语言、标题高度改写、同名实体、后续事件与事实冲突仍可能误分或漏分。没有对旧库做批量重新归类，也没有自动合并/拆分历史事件。

## 全文查询和兼容接口

SQLite 支持时创建 FTS5 trigram 索引，数据库触发器同步新增、修改和删除。长词使用索引加精确文本过滤，短中文词、特殊字符或不支持 FTS5 的 SQLite 回退到字面 SQL 查询，`%` / `_` 不会变成通配符。搜索范围是文章当前版本的标题、完整正文、来源域名；事件查询同时覆盖所关联文章的完整正文。历史版本通过版本接口查看，暂不建立历史全文索引。

API 与页面复用同一查询服务；过滤在分页之前，排序有 ID 兜底。新闻库和事件页提供上一页/下一页，保留筛选条件。采用 offset 分页：采集期间记录增加或事件排序变化可能改变后续页面，不是冻结快照。

| API | 用途 |
|---|---|
| `GET /api/articles/search`、`GET /api/articles` | 默认仍返回数组；新增 `offset`、`mode`、`paginated` |
| `GET /api/events/search`、`GET /api/events` | 同上，事件搜索涵盖关联报道全文 |
| `GET /api/articles/{key}` | 当前文章、版本号、事件关联及初次归并依据 |
| `GET /api/articles/{key}/versions` | `items/total/offset/limit`，倒序版本记录 |
| `GET /api/articles/{key}/versions/{revision}` | 不可变版本详情 |

查询参数：`mode=contains` 为连续字面文本；`mode=terms` 将空格分隔的词按 AND 查询，可分布在不同字段。输入不执行 FTS 运算符。`query` 最长 200 字符、最多 10 个词，`limit` 为 1–500，`offset >= 0`，无效输入返回 422。

`paginated=true` 返回 `items/total/offset/limit/has_more/search_backend`；旧数组返回值通过 `X-Total-Count` / `X-Offset` / `X-Limit` / `X-Search-Backend` 响应头提供分页信息。

示例：`/api/articles?query=人工智能%20芯片&mode=terms&duplicates=no&offset=0&limit=20&paginated=true`。

运行统计的 `stored_articles` 表示新文章数，`updated_articles` 表示内容更新数，`skipped_existing` 表示内容未变的重复抓取，`duplicate_reports` 表示本轮收录/更新的转载副本。兼容字段 `duplicates` 仍包含重复抓取与转载副本，页面分别展示。

## 升级

1. 停止旧服务及采集进程，备份 SQLite 数据库和整个 storage_root。不要同时运行新旧版本写入同一库。
2. 安装本版：`pip install news2douyin-0.5.0-py3-none-any.whl`，继续使用原 `--db-url`、`--storage-root` 配置。
3. 首次初始化新增版本、身份、采集观察和事件关联等表，为已有文章建立 `legacy_baseline` 快照并回填全文索引。不会重命名已有 ID，也不会删除旧副本。相同规范化 URL 已有多行时保留各行，以最早一行接收以后更新。
4. 旧快照表示升级时的库内内容，不伪造此前的修改记录。初始化可以重复执行，完成标记防止每次启动重新扫描全库。
5. 在新闻库搜索旧记录，查看版本，再采集一个有正文更新的 URL，确认产生新版本且事件文章数不增加。大库首次建索引需要额外时间和磁盘空间，本次未做生产规模迁移压测。

SQLite 是本次验收数据库；其他 SQL 后端、生产吞吐与多机部署未验证。版本与索引没有自动过期清理策略。
