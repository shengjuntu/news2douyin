# SQLite → PostgreSQL 迁移契约

实际部署命令、备份和回滚流程见 [PostgreSQL 运维说明](POSTGRES-OPERATIONS.md)。本工具面向停止旧服务后的维护窗口；本轮验证使用临时 SQLite 样本和真实 PostgreSQL 16.2，没有迁移现场的 27GB 数据库。

## 输入与停写条件

- 必须停止旧应用及所有写库进程，并传入 `--source-stopped`。该参数是操作者确认，不是工具能远程证明服务已停止。
- SQLite 使用 `mode=ro` 和 `PRAGMA query_only=ON`，在一个持续只读事务中读取一致快照。工具不执行 checkpoint、VACUUM、源表初始化或任何源写入。
- 拒绝非空 `-wal` 或 `-journal`。不要删除它们以绕过检查。停写后若有未合并 WAL，应由操作者使用 SQLite backup API 制作一致、干净的独立快照，或在明确维护操作中完成 checkpoint，再把该快照作为源。
- 已干净关闭的 WAL 模式库可直接作为源；SQLite 只读打开时可能创建空 `-wal` 和共享内存 `-shm`，工具允许这种运行记账变化，不要求删除旁路文件或更改数据库日志模式。非空日志仍会拒绝。
- 启动、各复制块及各表核验之间检查文件大小、修改时间、旁路日志和 SQLite `data_version`；结束再次比较源身份。源身份包括绝对路径、大小、纳秒修改时间和首尾各 1MiB 的 SHA256。检测到变化会失败，续传必须继续使用同一未变化的源文件。

这些检查用于发现意外写入；不能替代停服务，也不以修改时间和首尾指纹声称完成整个源文件的密码学认证。复制内容另外进行逐表全行核验。

## 目标与覆盖保护

首次目标必须是专用空 PostgreSQL 数据库。已有用户表、视图、物化视图或序列会拒绝，即使表为空；其他用户 schema 中已有对象也拒绝。不要先启动新 app 创建表后再首次迁移。

工具使用 PostgreSQL 会话级 advisory lock，阻止两个迁移同时写同一目标。断点表不属于日常应用模型；正常服务会拒绝启动 `phase` 尚非 `ready` 的迁移目标。已 `ready` 的目标也拒绝再次续传，以免向已上线库重放。

## 复制范围和保持条件

复制当前加载的全部应用 SQLModel 表，保留 ID、文章版本、原始字符串 JSON、来源回执、任务、租约、接收游标和投影 offset。Boolean 的 SQLite `0/1` 对应 PostgreSQL `false/true`；其他值会报错。旧版不存在的新模型表创建为空表，例如从 0.22 迁移时的 `GraphLease`。

源存在未知业务表或未知列时会拒绝，不能悄悄漏搬。SQLite 内部表和可重建 FTS 虚拟表及其确定的影子表不作为业务内容复制；排除清单会写入报告。应用的 PostgreSQL 搜索触发器、索引在复制及核验成功后安装，不预先运行完整初始化或回填。

所有原有租约均照原值迁移。停旧服务后，新服务可能需要等待旧租约自然过期：图租约默认 120 秒，其他任务按各自保存的期限恢复。不会为求立即运行而默默删除租约或图所有权状态。

SQLite `sqlite_sequence` 不是业务表，但其 AUTOINCREMENT 高水位参与目标序列修复；新 ID 大于当前记录最大 ID 和历史高水位，避免重用已删除记录的旧 ID。

## 分块、失败和续传

`--chunk-size` 默认 1000，允许 1–10000。复制使用单列或复合主键的 keyset，避免大 `OFFSET`；内存按块使用。每个目标块的插入和最后主键、累计行数、累计哈希在同一事务提交。

复制被终止后，保持源快照不变，在同一目标加 `--resume`。工具核对源身份和模型 schema，按已提交主键接续；未提交的块回滚，不会通过跳过一段行数来续传。续传完成后仍重新核验所有表，不能把旧的“已复制”状态视为成功证明。损坏或不一致的源、目标不自动覆盖修复；应保留诊断，再使用专用空目标从头迁移。

运行状态位于 `_n2d_sqlite_migration`，表级进度位于 `_n2d_sqlite_migration_table`。状态依次为 `preparing`、`copying`、`verifying`、`installing`、`ready`；异常标记 `failed`，保留已提交块供续传。异常输出只包含安全描述或异常类型，不输出原始 SQL 参数及数据库凭证。建议通过环境变量提供连接，避免连接密码留在 shell 历史。

## 完整性报告与切换

每个模型表都再次完整流式读取源和目标，比较总行数和按主键稳定排序的全行 SHA256 链。字符串主键使用 SQLite `BINARY` / PostgreSQL `C` 排序；标量值带类型标记和长度边界，Boolean 先规范化，字符串 JSON 不重新序列化。报告列出每表计数、两侧哈希、源是否存在该表、核验列和排除项。

仅当全部表核验成功、索引及运行触发器安装成功、ID 序列修复且源保持不变时，最终标记 `ready`。`--report-file` 保存相同 JSON 报告；禁止把报告写到源数据库及其旁路日志路径。

工具只迁移 SQLite 的应用事务状态。DuckDB 原档、下载 ZIP、运行产物、作品文件以及 FalkorDB 不搬动、不重写；继续使用相同 `storage_root`、图地址和命名空间。若更换主机或路径，必须另外迁移完整存储目录并核验历史绝对路径，不能仅靠此工具完成。完成后核对 `/setup` 后端、`/intake` 游标和计数、固定文章版本、专题研究及作品文件，再恢复后台运行。
