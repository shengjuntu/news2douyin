# 候选筛选与事件整理

WorldNewsAPI 按策略获取热门榜单或关键词结果。采集器保存本次实际取得的规范化报道和批次索引，再执行本地相关性筛选。采集批次可在运行记录中检查，候选索引可在雷达的「候选库」按关键词、信源或语种查询。上游搜索范围和返回上限决定这次有哪些材料可用。GDELT 的批次归档和 NewsNow 的快照继续提供各自的原始出处。

## 从同一批线索选材

- 每日精选从共同候选接口读取指定北京时间日期和出刊截止前的材料。默认使用 `balanced`，上限 100 条。Top N 算法和参数可通过现有 TOML 配置替换。[Top N 配置](TOPN-SELECTION.md)
- 焦点有独立的归集。后台为所有启用的焦点共用一次候选扫描，分别按关注范围匹配。新启用或调整范围时回查最近一天，再持续跟踪。补收的 GDELT 材料按实际到达时间归集。每个焦点每天最多安排 12 条带可核对片段的候选做模型复核。其余匹配仍保存在焦点里。已整理事件原有的历史回溯、证据和研究版本仍可查看。
- 候选页面和雷达卡片可打开同一个整理页面。需要做内容时，可以先「形成选题」，将有出处的材料快照带进工作台。

## 把材料写入事件

选择「整理事件」查看来源，然后「整理为新事件」，或者搜索并选择已有事件。服务端根据候选编号再读取来源，检查提交时的材料和目标事件版本，保存采用记录和所用报道版本。单独重复提交同一个请求会返回对应的事件。标题、摘要和榜单线索仍以待补原文的材料保存。

WorldNewsAPI、定向 GDELT 和普通接入文档默认只进入候选或新闻库。现有事件中的同一报道可以更新原文版本。旧版演示模式和显式启用的 `NEWS2DOUYIN_GKG_AUTO_EVENTS=1` 仍通过统一入口执行已配置的自动归属，并写入决定原因。采集批次原档、已发布日报和既有事件可继续读取。

FalkorDB 活动图按已整理事件及其报道关系异步更新，已知关系也可为焦点补充候选。透过候选编号可以追到原始资料。全局活动图和每个焦点的图继续各自提供关系和研究上下文。

## 增加语种

在信源策略指定语种。来源代码或显示名需要映射时，用语言配置管理，候选和报道保留来源标识。日报、焦点和整理页面读取统一语种字段。[语种配置](LANGUAGE-CONFIG.md)

## 升级

按现有方式备份并安装后重启。PostgreSQL 和 SQLite 在启动时创建候选表、索引和焦点线索表。旧采集批次仍可从运行记录查看，升级后的正式采集采用新的候选索引。已有 GDELT 原档、NewsNow 快照和已整理事件继续通过各自的入口读取。
