# 0.8.0：事件专题、发展脉络与证据

本版让“事件专题”成为可以实际整理资料的工作区。每日采集和选题仍从首页开始；需要理解背景、对照多篇报道时进入 `/events`。

## 建议使用流程

1. 打开自动归并的事件，或在事件列表新建一个专题。
2. 在“报道资料”中按关键词和日期查新闻库，将相关报道加入专题；错误关联可以移出。
3. 在“发展脉络”添加进展：标题、说明、日期含义、确定程度，以及支撑它的文章版本和原文摘录。
4. 从“专题关系”关联背景、后续或相关专题。确认重复的专题可合并；混入不同事件的报道可拆出。
5. 在“补充检索”按关键词、发布日期范围、国家与语言查询，阅读候选后勾选收录。
6. 导出证据包供进一步写作，或继续使用原来的“根据报道生成模板草稿”。

本版的脉络由用户整理，没有自动提取事件经过或自动核实事实。0.9.0 将把已整理的脉络接入逐段有来源的深度脚本；本版模板草稿仍读取关联报道。

## 新闻、事件与时间的关系

| 对象 | 含义 | 编辑后的影响 |
|---|---|---|
| 新闻库报道 | 新闻源返回的报道及其内容版本 | 新采集可以产生新版本，旧版本保留 |
| 事件专题 | 对同一件事组织的一组报道 | 增删只改变关联，原新闻继续在库中 |
| 进展节点 | 用户整理的一项进展、时间说明与引用 | 固定引用文章版本、内容指纹和摘录 |
| 背景 / 后续关系 | 当前专题与另一个专题的关系 | 表示关联，不自动合并报道 |
| 原“时间线”入口 | 新闻长图排版 | 保留为辅助工具，与事件脉络区分 |

节点可标为“发生日期”“报道日期”或“时间未知”。目前按来源描述记录到日，支持起止日期区间；具体时分、时区、相对时间与争议说明写在“时间依据”中。不把一篇报道的发布日期自动当作事件发生时间。

确定程度分为来源明确记载、大致时间、有争议、未确定。大致或有争议时须填写说明。未知时间节点不接受猜测日期，排列在已知日期节点之后。“我已核对”表示编辑确认，不代表系统保证事实正确。

## 来源与变更保护

- 每个节点至少引用一篇当前专题中的报道，最多 20 篇。摘录必须是该文章版本标题或正文内的连续片段；不接受编造摘录或拼接成一句。
- 报道后续更新不会替换已保存节点的证据。页面提示“已有新版本”，仍链接到当时引用的版本。
- 正在被节点引用的报道不能直接移出专题；先修改引用或删除节点。
- 同一报道可以在多个专题中出现；副本/转载继续沿用现有文本去重标记。不同域名并不必然是独立事实证据。
- 人工编辑的专题标题、摘要保存在独立状态中，后续自动采集不会覆盖。
- 专题编辑带版本检查。其他窗口已修改时会返回 409，保留当前表单，提示刷新；不会静默覆盖他人修改。
- 删除节点保留原内容与引用的操作记录。页面展示最近 50 次操作，数据库保留完整历史。

## 合并与拆分

合并将当前专题的报道和活动节点转移到目标专题；共享报道只保留一份关联。原专题不删除，原地址提示打开目标，历史脚本继续按原地址查询，不改写其内容。默认事件列表隐藏已经合并的专题。

拆分选择一组报道并创建新专题。完全引用这组报道的节点一同移动；如果节点同时引用将被拆开的两组报道，则要求先整理节点。拆分后自动建立两个专题的关联。合并、拆分都有操作记录；本版没有一键撤销整次合并，必要时可依据记录重新整理或拆分。

背景关系有方向：选择“当前事件的背景”意味着所选专题是当前专题的背景；另一侧会显示相反方向的说明。专题合并后，已有关系会解析到合并后的专题。

## 两种关键词检索入口

| 入口 | 适合用途 | 新闻何时入库 |
|---|---|---|
| 策略页 → 获取方式 → 主动关键词检索 | 每天自动追踪某一主题，也可试跑 | 正式采集执行筛选、去重、版本与事件关联；试跑不入库 |
| 事件专题 → 补充检索 | 为一个事件找背景与后续资料 | 先保存候选；用户勾选后才入库并加入当前专题 |

均接入 WorldNewsAPI 的 `search-news`，使用服务端 `API_KEY`；策略仍支持原有 `api_key_env` 高级配置。关键词支持 3–100 个字符，单次 1–100 条。上游默认要求空格分隔的多个词同时匹配；过窄时应放宽查询。当前只取一页，可以收窄日期或改词再次检索，不声称覆盖全网或穷尽相关资料。

专题检索记录保存查询条件、创建/完成时间、候选结果、上游匹配数量、错误及收录映射。选中已有 URL 时保留库内当前正文与版本，不用可能更旧的检索结果覆盖它；原候选仍保存在检索记录中。新收录文章标记为 `external_research`，文章版本记录指向检索编号。

网络检索在保存请求记录后执行，有连接与读取超时。页面返回前等待请求结果；关闭页面后可从最近记录查看已保存结果。若服务进程在请求途中停止，记录可能保留“请求中”，需要重新检索；本版不为补充检索提供持久队列重试。自动采集和策略试跑继续使用已有的持久任务队列。

关键词检索不使用热门榜缓存，每次可能消耗账户额度。400、401/403、402/429、超时和网络错误给出相应提示，不记录或输出 Key。新闻源无时区的发布时间按 UTC 解释，沿用现有采集约定；查询的自然日边界按所选时区转换为 UTC。源端日期归属与正文表达仍需用户核对。

候选正文由 API 提供，若只有摘要则注明；超过 50,000 字符的单篇正文截断并标明。外部收录进入新闻库，可按发布时间或首次入库时间查询；它不伪装成某次正式采集任务的结果。

接口依据：[Search News 官方文档](https://worldnewsapi.com/docs/search-news/) · [API 认证](https://worldnewsapi.com/docs/authentication/)。请求用 `x-api-key` 头，不把凭据放进查询或证据包。

## 证据包

“导出证据包”下载 JSON，包含专题、当前节点、引用摘录和版本标识、关联专题、最近整理记录、当前来源版本的完整已保存正文，以及节点引用的旧版本正文。外部新收录文章另附检索条件和收录映射。导出在同一次数据库锁定期间读取，避免混入两个整理版本。

该文件是可追溯的材料包，不是已经制作的视频或审定成稿。未引用的删除节点完整历史仍在数据库中；导出中的操作列表只含最近 50 次。

## 从 0.7.0 升级

1. 停止服务，备份原数据库和整个运行目录。
2. 解压本包，在原环境执行 `pip install -e .`，或安装 `release/news2douyin-0.8.0-py3-none-any.whl`。
3. 保留 `.env`、原 `--db-url` 和 `--storage-root`，按原参数重启。
4. 程序自动创建新的专题状态、节点、关系、操作与检索表。原新闻、内容版本、每日选题、脚本、任务、策略状态及计划不重建。
5. 进入一个原有事件，试着添加节点；再在策略页检查新的获取方式。旧策略默认继续使用热门榜。

仍采用 Python + HTML，仍以 SQLite 为验证范围；没有改动独立 RunDesk 应用、已有视频渲染链路或其依赖要求。

## 新接口

- `POST /api/events`：新建专题。
- `GET|PUT /api/events/{key}/workspace`：读取工作区或编辑标题、摘要、主题。
- `POST /api/events/{key}/sources`，`DELETE /api/events/{key}/sources/{article_key}`：管理报道关联。
- `POST /api/events/{key}/moments`，`PUT|DELETE .../moments/{moment_key}`：管理脉络。
- `POST .../relations`，`DELETE .../relations/{relation_key}`：管理关联。
- `POST .../merge`、`POST .../split`：合并、拆分。
- `POST .../research`，`GET .../research/{research_key}`，`POST .../research/{research_key}/import`：补充检索与收录。
- `GET .../evidence-export`：下载 JSON 证据包。

工作区修改请求必须携带读取到的 `expected_version`；合并还需要 `target_expected_version`。DELETE 请求同样使用 JSON 请求体携带版本。旧查询接口和脚本接口继续保留。
