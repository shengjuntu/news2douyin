# 一键 Docker 深度新闻研究

配套版本：news2douyin **0.14.0**、RunDesk **0.48.0**。首次准备镜像、回调地址和模型认证后，新闻研究页的“启动环境并深度研究”会自动准备该应用绑定的容器，检查认证及 MCP 工具，再提交研究。容器和会话由 RunDesk 管理，课题、证据、报告和业务运行记录保存在 news2douyin。

## 首次部署

1. 升级两端，保留各自数据目录；升级前停止服务并备份数据库、研究配置与工作区。RunDesk 构建并部署 `rundesk`、`kun` 两个程序。当前托管 Docker 路径要求 Linux 本机 Docker Engine；确认服务账户有权访问 Engine。
2. 在 RunDesk 源码目录生成 news2douyin 构建包。将 `X.Y.Z` 换成部署环境明确选定的 Codex 版本，不能填写 `latest`：

   ```bash
   python3 examples/news2douyin/run.py pack --codex-version X.Y.Z --output ./build/news2douyin.zip
   ```

   上传 RunDesk 的镜像构建页，Dockerfile 路径填 `Dockerfile`，完成构建并记下镜像名称/版本。也可使用该目录的 `build` 命令在同一 Engine 构建。当前配方默认 Exa + Agent-Reach 完整基础工具链。也可直接在 RunDesk 初始化向导中选择新闻研究镜像，无需手动上传 ZIP。账号 Cookie、代理和可选平台服务仍在运行时配置。
3. 安装并启动新闻服务，例如在可信部署网络中：

   ```bash
   python -m pip install -e '.[research]'
   news2douyin-server --host 0.0.0.0 --port 18080
   ```

   服务需要能被研究容器访问。只监听 `127.0.0.1` 不能接受经宿主网关进入的连接；请用防火墙或受保护的反向代理限制访问，新闻管理页面本身不提供完整多用户认证。
4. 打开 `/research/settings`，填写 RunDesk 地址、管理凭据、运行方式 **Docker**、已构建镜像，Docker 中的 Codex 权限选 **完整访问**，研究外部搜索固定由 Codex 调用 **Exa**，镜像需包含对应工具。点击 **连接并配置环境**。
5. 同机的 localhost 回调自动转换为 `host.docker.internal`；跨机器或代理部署，在“Docker 回调地址”填写容器实际可达的 news2douyin 基础地址，例如 `http://192.168.1.20:18080`，不要附加 `/mcp/research`。应用访问地址用于浏览器跳转，与容器回调可以不同。
6. 点击“在 RunDesk 中管理”，为 **该应用的 Docker 环境** 配置模型提供方与认证。宿主机已有登录不会自动复制到容器。回到新闻设置页“检查连接”，确认认证、`news2douyin-research` 和选定的搜索工具可发现。检查连接会启动/复用容器，不运行模型。

首次连接只补装容器缺失的业务 MCP 和 `news-research` Skill；显式连接配置会启用 Exa，保留其自定义地址与认证。成功初始化后，重连不会恢复已删除或关闭的业务 MCP/Skill，也不会替换不同的回调地址。选择“完整访问”再连接时，会明确更新审批策略；选择“沿用 RunDesk 现有权限”则保留审批设置。镜像或资源变更要在 RunDesk 显式更新环境，不会在开始新闻研究时自动部署。

## 从 0.13.0 修复反复授权

1. 先停止正在运行或等待审批的研究，升级 RunDesk 0.47.1 与 news2douyin 0.13.1，沿用原数据目录和数据库。
2. 打开研究设置，保持已有镜像、回调和凭据，Docker 权限选“完整访问”，点击“连接并配置环境”。仅保存设置不会改变运行权限。
3. 新一轮研究使用 `danger-full-access`、`approvalPolicy=never`；当前容器已启用 MCP 的服务默认及已有工具审批覆盖均设置为 `approve`。服务器/工具禁用列表和输出上限不变。以后新增 MCP 后，再连接一次以应用同样策略。
4. 已弹出的审批不会自动接受。停止旧研究后重新开始，检查连续读取不同 source_id、不同 offset 均不再要求调用授权。真实 MCP 数据填写、OAuth 登录或组织强制策略仍可能需要交互。

权限保存在该应用实例及对应环境的 CODEX_HOME 中，重启容器后仍保留。其他应用与本机实例不变；“沿用”只停止覆盖权限，不撤销已经保存的完整访问设置，撤销请到 RunDesk 的运行权限和 MCP 配置修改。若容器里的 Codex 不支持官方服务级 MCP 审批配置，需选定兼容版本重建镜像。

## 挂载与完整访问的范围

容器可读写挂载的项目工作目录、独立 CODEX_HOME、独立 HOME；轨迹、租约和 RunDesk 运行程序只读挂载。宿主机对应的可写文件会被同步修改，产物保留在工作区。新闻服务的数据库与证据仍由服务及业务 MCP 管理，并非自动挂载整个新闻应用目录。

完整访问关闭 Codex 自身的执行沙箱与逐次审批，容器的系统根目录仍只读，权限仍受容器用户、网络模式和资源限制。没有 privileged 模式，也没有 docker.sock 挂载。需要系统依赖时在镜像构建阶段安装；项目依赖可安装到可写目录。

## 日常使用

选择新闻并建立研究课题，核对目标、时间截止点与预算，点击 **启动环境并深度研究**。页面依次显示排队、准备环境、开始执行及研究进度；运行详情记录环境编号、镜像 ID、会话、检索记录、证据和报告版本，可跳转 RunDesk 检查执行轨迹。

同一课题运行期间重复点击会返回已有运行，不创建第二个模型任务；追加不同要求使用追问入口。停止会阻止尚未提交的任务或停止当前运行，不等于立即删除容器。容器继续由 RunDesk 的租约与空闲回收策略管理。

新任务会重新检查环境。没有模型认证、业务 MCP 或搜索工具时显示具体原因，不能把“应用已登记”当成“已经可以研究”。准备过程不占用正式研究的时间预算；开始模型任务后计时。

## 新闻研究与搜索的关系

| 环节 | 当前行为 |
| --- | --- |
| 检索计划 | `research_search` 保存查询与时间范围并预留预算，返回选定 MCP 的工具与查询 |
| 外部搜索 | Agent 调用 Exa；`research_record_search` 将实际返回的候选 URL、摘要或错误关联到本轮票据 |
| 原文证据 | `research_read_source` 由新闻服务获取允许的公开 HTTP/PDF 来源，保存原文和引用位置 |
| 研究判断 | 将可核对引用关联到判断，明确未知、冲突与材料缺口，再保存报告 |

搜索摘要只作线索，不直接写成原文证据；搜索记录标注为 Agent 报告的 MCP 结果，不能视为服务端独立验证过的搜索响应。当前使用 Exa 的搜索入口；原文读取失败仍需报告缺口。

搜索票据受到 news2douyin 的计数和运行状态检查，但直接调用外部 MCP 的顺序仍依赖 Skill/提示约束；它不是对所有 Agent 工具调用的硬配额或费用上限。保留必要的人工核稿，尤其是日期、独立来源、因果判断和争议表述。

## 升级与故障定位

- 旧研究设置继续保留本机模式和原搜索提供方。希望使用一键容器研究时明确切换 Docker 并完成首次配置；历史研究与提交回执保留。
- 新增 `ResearchEnvironment` 表保存每轮运行方式、搜索选择和环境检查结果，通过现有建表流程添加，不改写历史研究表。
- 新安装默认 Docker + RunDesk/Exa。旧设置的 Wigolo 迁移为 Exa；新任务不再选择 Wigolo。
- `environment_update_required`：管理员已更改镜像或资源，请在 RunDesk 更新环境。
- `application_binding_changed`：绑定或配置在检查期间变化，重新连接并核对后重试。
- MCP 缺失/不可达：先检查容器回调、服务监听地址、MCP 是否启用，再看 RunDesk 轨迹与配置错误。
- 模型失败：认证检查仅证明配置和发现通过，不验证额度、模型权限或真实推理质量。

当前代码验收范围见 [验证记录](validation-0.13.2.md)。真实 Docker 构建、Codex 认证、在线搜索和新闻研究质量仍须在部署环境验收。

## 升级到 0.13.2

保留 `62ed074` 合入的普通请求超时、容器准备超时及 revision 冲突重试。保留 Docker 完整访问与持续 MCP 授权。

1. 停止旧的活动研究，升级 RunDesk 到 0.48.0，沿用数据目录。
2. 在初始化向导选择“仅使用 Docker 应用”，展开应用 Docker 环境，准备新的 news2douyin 镜像。默认标签 `rundesk-news2douyin:exa-agent-reach`；无需宿主机 Codex/Node/Python。
3. 在原 Python 环境安装本包：`python -m pip install -e '.[research]'`；或依赖已齐全时安装 `release-0.13.2/news2douyin-0.13.2-py3-none-any.whl`。重启新闻服务。
4. 新绑定填写镜像标签；旧环境更换镜像需先在 RunDesk 显式更新。点击“连接并配置环境”，启用 Exa、停用旧 Wigolo MCP。自定义 Exa 地址与认证信息保留。
5. 完成模型认证，检查业务 MCP 和 Exa，然后做一次真实研究。已有研究来源快照不会被改写。

镜像准备成功只代表离线工具可用，不等于全部 Agent-Reach 渠道已登录。小红书等额外 MCP 服务不内嵌，按需配置。当前源码包未发布公共镜像。

0.14.0 已统一研究搜索入口，详见 [研究检索职责与迁移](RESEARCH-SEARCH.md)。本地新闻库查询不占外部预算，旧研究路径需停止后在原课题开始新一轮。
